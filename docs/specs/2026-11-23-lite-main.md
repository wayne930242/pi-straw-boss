# A lighter main: no graph steer, no plan-first block, a pinned section, a worker cap, fewer tools (2026-11-23)

Status: implemented on `feat/lite-main` (base `main` 94d5523c, 0.82.1), for 0.83.0. How it behaves for a user: [how-it-works, How it works](../how-it-works.md#how-it-works) (rule 5, "The role section stays put") and [Tools](../how-it-works.md#tools).

## Boss words (binding)

> 「B1 可以做」

B1 is proposal L2's first half in the lightweight-orchestration review of 2026-11-23: drop the plan-first block and the graph steer. Of B2 the boss took the conditional half, as his main relayed it: register `train_car` only where the workspace has an app with `integration`, `link_request` only where Straw Link is set up, and decide for `boss_server` (keep it if a main uses it). No other tool is renamed or merged.

## Before

- A coordinator's role section held `main.md` only. Once its todos named a graph in `metadata.graph`, `briefing.ts` steered `dispatch.md` and the graph's addendum (`graph-fan-out.md`, `graph-orchestrator-worker.md`) into the conversation, and steered again at every change of the graph: "Your plan's graph is now single-loop. Add to your instructions: ## Dispatch …", "Your plan has no open graph: drop your "## Dispatch" and "## Graph:" sections." One session got about 8 such steers, each repeating the same text.
- A coordinator's `worker` dispatch was refused with `sb: plan first: …` until its todos (or a `todo` call earlier in the same assistant message, `planmsg.ts`) named a graph. A main that forgot lost a turn.
- `boss_duty` rewrote the `straw-boss` system section at the next run, the one exception 0.81.0 kept when it pinned the section ([0.81.0](../releases/0.81.0.md): 53 full prompt-cache rewrites, about 8.9M cache-write tokens in 48 h on one Mac).
- No code capped the workers of a main. `planning.md` named a cap of 4 that only the model kept; pi-herdr-agents caps persistent specialists only (`persistent.maxAgents`).
- Every main had `train_car` while integration was on and `link_request` always, whether or not a call could succeed.

## Decisions

| # | Question | Decision |
|---|---|---|
| L1 | Where the dispatch rules live | In `main.md`, once, for every kind: split work by owning app, a todo before each worker, `blockedBy` for dependent tasks, worktrees under `~/.herdr/worktrees/<repo>/<branch>` for parallel writers, work independent of the main's chain to subagents in parallel, at most 4 workers. `dispatch.md` and both graph addenda are deleted. `planning.md` stays a reference that `main.md` points to (the plan's todos, anchors, checkpoints), and so does `apps-config.md`. |
| L2 | What a graph still does | It labels the page beside the kind (`planGraph`, `items.ts`). No prompt, steer, or gate reads it. |
| L3 | `boss_duty` and the section | The section is pinned at the first run with a role and its labels, and nothing rewrites it until the next session start, `boss_duty` included. The new kind's whole prompt reaches the model as one steer, as a role change and a kind migration already did; compaction and `/tree` resend it. A `/reload` (a new session start) renders the current kind in its section. This reverses the one exception 0.81.0 kept. |
| L4 | The worker cap | 4 `worker` subagents per session at once, counted from pi-herdr-agents' registry of the children this process still waits on (`Symbol.for("pi-subagents/runtime")`, the slot `orphan.ts` reads), plus the worker calls admitted since the turn began: pi prepares every tool call of a message before any runs, so a message of five `subagent` calls is held to four. Scouts, planners, reviewers, watchdogs, other roles, a bare spawn, and `subagent_resume` are not counted. A registry that cannot be read holds nothing back. |
| L5 | `train_car` | Registered in a train, or in a session whose project's apps.json (`projectAppsDir`, else the nearest above) names an app with an `integration` object, with integration on and an sb server (as before). |
| L6 | `link_request` | Registered where Straw Link is in use (an unattended policy, a team in config.json, a team file, or the link enabled) and the computer is attended. An unattended computer refused every call already; the tool is gone there. A tower run registers its own as before. |
| L7 | `boss_server` | Kept. Mains call it: 18 main sessions from 11-03 to 11-23 called `status`, `logs`, or `restart` (a search of the session files on the Mac, besides 30 tower runs). |
| L8 | When the tool list is decided | At each session start (`s.toolSet`, set by a `session_start` handler in `index.ts`), whatever the join does later: a tool list that changes mid-session busts the prompt cache as a rewritten section does. A switch or a team changed before a slow join, or after it, reaches the tools at the next session start (a `/reload`; a `/new` in the same process keeps the tools the first join registered). `boss_server` depends on the sb server deps alone, which never change in a process. (Added on the lite-plan review of 2026-11-23: "Fix the conditional tool set at session start".) |

## 1. No graph steer, no plan-first block

`briefing.ts` briefs a role and a kind, nothing else (`Briefed { name, duty }`). `steerChange` sends the whole role prompt for an unknown state, a role change, or a kind change; the delta steers are gone, and so is the `todo` result's rebrief. `session.ts` drops the gate and `planmsg.ts`. `mainDuty.graph()` is gone; the page reads `planGraph` itself.

## 2. A pinned section

`begin` pins the section once per session start and never again (`rewriteKind` and `kindDeclared` are gone). The steer bookkeeping of 0.81.x stays: what the model holds counts from pi's delivery, one steer waits in pi's queue at a time, and a branch's prior whole steer is reused at the first pin only while the model still sees it and it carries the current text.

## 3. The cap

`src/workercap.ts` (`createWorkerCap`): `admit` on `tool_call` of `subagent`, `ran` on its `tool_result`, `settle` on `turn_end` (a call another extension blocked leaves no result). The refusal: `sb: 4 workers run for this main already (<n> running, <m> starting in this message): wait for a result, then dispatch the next; a scout, a planner, a reviewer, or a watchdog may run now.`

## 4. The tools

At each `session_start`, `index.ts` sets `s.toolSet = { link: link.inUse() && link.attended(), cars: <integration on and an sb server>, carApp: hasIntegrationApp(cfg.cwd()) }` (`cfg.cwd`, new, defaults to `process.cwd()`; `inUse` is now on the link's API). `trainCarTool` registers when `cars` and `s.isTrain || carApp`; `addNetTools` registers `link_request` when `link`.

## Sizes (measured in the test world, 2026-11-23)

| | Before (0.82.1) | After |
|---|---|---|
| A coordinator's section, integration on / off | 4,880 / 2,821 characters | 5,493 / 3,415 |
| Steers over one plan (graph set, changed, closed, set, cleared) | 5 steers, 1,937 characters | none |
| The plan-first refusal | 359 characters, and a lost turn | none |
| A `boss_duty` | the section rewritten: the whole conversation sent uncached | one steer of the new kind's prompt |
| A main's sb tools (integration on, Straw Link set up, an integration app) | 13 | 13 |
| … with no Straw Link | 13 | 12 (`link_request`, about 2,100 characters of description and schema, gone) |
| … with no app with `integration` | 13 | 12 (`train_car`, about 2,000 characters, gone) |
| … neither | 13 | 11 |

The section grows by about 600 characters, the size of one graph steer, and it is cached for the session; the steers it replaces were sent again at every change of the graph.

## Tests

`tests/lite-main.test.ts` (red first, against 0.82.1): no steer on any `todo` change and the same section bytes; the dispatch rules in the section on and off; no plan-first block; the section unchanged by `boss_duty`, whose kind arrives once as a steer; the cap of 4 across one message and the registry; the tool list in four setups (integration off, no link, no integration app, both on); the tool list unchanged when integration and Straw Link turn on, or off, between the session start and a held-back join, and again before a `/new` (red with the decision read at the join). `tests/section-stable.test.ts` drives the steer bookkeeping with kind changes instead of graphs; `tests/duty-session.test.ts`, `tests/duty-prompts.test.ts`, and `tests/prompts.test.ts` follow the fold.

## Known limits

- A main started outside its project's folder (in a parent with no apps.json above the app) has no `train_car`. An integrator opens in the project's checkout, and a train always has it.
- A team set up during a session reaches `link_request` at the next `/reload` or pi start (L8).
- The cap counts the workers this pi process launched; a worker a revived main inherits (`inherit.ts`) is not in pi-herdr-agents' registry and is not counted.
