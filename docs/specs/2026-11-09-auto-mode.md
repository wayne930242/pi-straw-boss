## What sb has today

- **Where a wait is seen.** sb loads in every pi in Herdr, subagents included. The bridge, the trust relay, and the ctx.ui wrap run before the child return (`src/index.ts:54-58`, return at `:59`). A pi outside Herdr runs no sb at all (`:51`).
- **Dialog owners** (`src/owners.ts:154-163`):
  - **Take a cancel:** `rpiv` (`ask_user_question`), `uiPrompt` (`ctx.ui.select`/`confirm`, `src/intercept.ts`), `linkGate`, and `linkRequest`.
  - **Take no cancel:** `robotHand` and `secretDrop`. pi-robot-hand 0.5.5 ends them only on an answer or the tool's abort signal (`src/dialog.ts:56-73`, `src/secret-drop/index.ts:254`).
  - **Not relayed, only counted:** `input`, `editor`, and `custom` (`src/intercept.ts:31`).
  - **Shared by commands.** The wrap patches pi's one shared `uiContext` (`intercept.ts:5-6`), so command handlers use it too. It knows which tool calls are in flight (`flying`).
- **What sb can stop.**
  - `tool_call` handlers refuse calls, and a handler that throws blocks the call (`src/link/hooks.ts:84`).
  - `tool_result` handlers rewrite results.
  - A message sent with `deliverAs: "followUp"` after `ctx.abort()` sits in the queue until the next `prompt()` (pi 1.3.0 `agent-session.js:1825-1852`, pi-agent-core `agent.js:250-268`). Only `triggerTurn: true` starts a turn.
- **The head run's turn starter.**

  - The boss's typed input in the head pane sets `bossTurn` instead (`runmode.ts:398-403`).
- **Towers never ask.**
  - A tower run has no question tool. A boss wait is a wait card.
  - `call_tower` returns at once (`src/tools.ts:59`).

- **Doors for the boss.**
  - `/boss` writes are refused without a screen and in runs (`src/boss.ts:73`).
  - GUI writes need the page token and CSRF.
  - The control socket has no peer credentials (train-workers §24).

## Terms

- **Auto mode** (自動模式): this computer's state in which the boss is away and nothing waits for them.
- **Park**: hand a decision over for the boss's return instead of waiting (per kind, §4).
- **Return list** (回來清單): what auto mode leaves for the boss when it ends (§8).

## Design

### 1. State: one file per computer, written only by the server

`<state>/auto.json` (mode 600), at the state root, so every Herdr slot reads the same file:

```json
{ "v": 1, "rev": 7, "on": true, "since": "2026-11-09T15:10:00Z",
  "by": { "via": "pi" | "gui" | "phone" | "head", "name": "…", "said": "我要睡了" }, "hash": "<sha256 of the rest>" }
```

- **Only the server writes it.** `/boss auto` asks the server, and starts it first when it is down, as `/boss server` does.
- **Write order** (AM2-F008):
  1. The server writes `auto-own.json` first. It holds the new `rev` and hash, the pending confirm (§2), and the used words (§2).
  2. It then writes `auto.json` through a temporary file and a rename.
  3. At start, it accepts an `auto.json` whose `rev` and hash match either the own record or that record's successor. A crash between the two writes therefore never makes the boss's own switch look foreign.
- **A lost or broken `auto-own.json` is not a foreign write.** When the server starts and the own record is missing or unreadable but `auto.json` parses, it adopts that file as its own state (logged `auto-foreign: own-missing`, listed on the return list; the used words start empty). It never writes the default off over it, so no session is told the boss is back (AMC-F004). A parseable `auto.json` that disagrees with an own record that does exist is foreign and put back, as below.
- **Secondary Herdr slots follow the primary** (AMC-F002). Only the primary server writes the files; a secondary server answers `auto-check` from them, forwards `auto-state|on|off|confirm|note|decided` to the primary's socket, and its tower service reads the primary's state for the brief line, the parking at switch-on, and the unparking and the head's end event at switch-off. In a secondary slot the head's `boss_auto` is refused (use the page's switch or `/boss auto` in a session) and the backstop (§5.2) does not run; the sessions' own cancels do.
- **A foreign write is put back as a new own write** (`rev + 1`) at the server's next poll (2 s) or at its start. It is logged as `auto-foreign` (no content) and listed on the return list.
- **Sessions read it in two steps** (AM-F002):
  - **Refusing new calls** (§3) follows the file at once. It is checked at `session_start`, by the 2 s stat poll, and on each guarded call. A refusal is reversible.
  - **Every transition waits for the server's check.** That covers the cancels and notice of on (§4, §5) and the end message of off (§8.5). The session asks `auto-check { rev, hash }` and acts only when the server answers that the write is its own. It acts once per confirmed `rev` (AM2-F008). With the server unreachable, it waits.
  - **What a foreign write can do.** It cancels nothing and tells no session that the boss is back. A foreign `off` lets new questions open for up to 2 s; the put-back's new `rev` is a confirmed on, so those questions are cancelled with the rest.
- **A file that does not parse keeps the last good state** the session read. A session that never read one asks the server; if the server is down, it treats auto mode as off. A notice says `auto.json is unreadable`, and the server lists it.
- **The trust question** comes before `session_start`. Its handler reads `auto.json` and `auto-own.json` synchronously through `src/autostate.ts` (AM-F010). It answers "no" only when the two match (AM2-F009); otherwise pi asks as usual, and the handler notes it.

### 2. Who turns it on and off (D1)

| Door | On | Off |
|---|---|---|
| **pi (first):** `/boss auto` | `/boss auto on` stages; the same handler then draws a terminal confirm (below) | `/boss auto off` |
| **GUI (mirrors):** `POST auto {on}` | Header chip, two taps. The second tap, 「代理不能再問你，正在等你的提問會被取消」, is the confirm | One tap |
| **Head tower:** `boss_auto({ on })` | Stages, when the boss's words in the turn match the on-list (below) | Switches, when the boss's words in the turn match the off-list |

- **`/boss auto` alone** shows the state, a pending confirm, and the last return list.
- **Who is refused.** `/boss auto` is refused without a screen, in runs, and in a Straw Link remote turn. The `auto` route refuses run tokens and operate sessions, and allows paired devices (D1).

**On is never one step (D9, AM2-F003, AM2-F005).** The server's only way to turn auto mode on, outside the GUI's two taps, is to confirm a pending record:

- **Staging.** Every `on` request over the control socket stages one: the head's `boss_auto`, `/boss auto on`, and any other caller. None of them switches. The record is `{ id, said, from, at, expires }`, kept in `auto-own.json`, and `boss_auto` answers `pending: not on until the boss confirms (10 min)`.
- **Lifetime.** A pending record expires after 10 minutes. It is cleared by its confirm, by any later switch, or by a newer staging, which replaces it.
- **Stale confirms.** A confirm names the pending `id`. A confirm for an id that expired, was cleared, or was replaced is refused: `This request expired or was replaced: ask again`.
- **Expiry is said.** When a pending record expires unconfirmed, the server sends the head one event (`Auto mode was not started: the boss did not confirm within 10 minutes`). The head says so in the conversation, and the GUI chip stays off.
- **The confirm, in phase 1.**
  - **GUI.** A button 「確認進入自動模式」, with the pending's `said` and age, on the head page and the Zen strip. It posts `auto/confirm { id }` with the page token and CSRF.
  - **pi, any pane.** `/boss auto on` and `/boss auto confirm` draw `ctx.ui.confirm` in that terminal. The dialog is marked so the wrap does not relay it, so only the keyboard answers. A Yes sends `auto-confirm { id }`.
  - **The head pane.** When the turn the boss typed there staged the record, the run's own extension draws the same terminal confirm. This is code, not the model; `/boss` is refused in a run (`src/boss.ts:73`).
- **Off needs no confirm** (D9), because it cancels nothing.
- **The head's check is code, not the model's word** (AM-F001).
  - `boss_auto` takes no event id. The server takes the turn's starter from the run's own report (`turn`, from `turnStarter`), and acts only if all of these hold:
    1. the caller's `who.kind` is `head`. A workspace tower's token is refused even if a hand-edited `--tools` lists the tool.
    2. `runs.bossTaken(token, turn)` holds, and the event is not a press. A wait-card press is a `boss` event whose text quotes the card, which the model wrote (`src/server/waitpress.ts`; `press: true`), so it never counts (AM2-F001).
    3. that event's text, read by the server through `runs.bossEvents`, matches the list for the direction asked.
  - **The word lists** are fixed in `src/autostate.ts` (AM2-F006):
    - **On:** 我要睡了, 準備休息, 睡前最後一輪, 進入自動模式, auto mode on.
    - **Off:** 我起床了, 我醒了, 結束自動模式, auto mode off; and 早安 only as the whole line or its start.
    - The match ignores case and spacing, and reads the whole line (up to 2,000 characters; `said` keeps 200).
    - **A line does not match when:** it holds both lists; a negation (不要, 先不, 還沒, 不是, 別, don't, not) is within 6 characters on either side of the phrase; or it ends as a question (嗎, 呢, ?, ？).
  - **The boss's typed turn in the head pane** (`bossTurn`, with no event) counts the same way. The run's extension reports the typed line that started the turn (`typed`) and a per-run turn number (`seq`). Both are set at the idle `input`, moved at `agent_start`, and cleared at `agent_settled`, as `turnStarter` is.
  - **Each event or typed line works once** (AM2-F007). Used event ids, and `(run id, seq)` for typed lines, are kept in `auto-own.json`, so a server restart does not reset them. The matched words go to `by.said`.
  - **Refusals.** Anything else gets `Auto mode changes only on the boss's own words in this turn (for example 我要睡了 or 我起床了), or /boss auto in pi, or the GUI switch.`
- **No tool turns it on or off** outside the head's `boss_auto`. No session has one.
- **Every switch and every staging is told and recorded** (AM2-F005).
  - It records the requester as the request reports it: session, pane, and pid. That goes in `by` and on the return list.
  - It sends `ctx.ui.notify` to every joined pane: `Auto mode on|off|pending (<door>, <name>)`.
  - A `tower-event` to the head records its requester the same way.
- **What remains possible** (AM2-F005). The control socket has no peer credentials (train-workers §24), and the GUI token is in `gui.json`. Any same-user process, which includes any agent with `bash`, can therefore do the following:
  - **Turn auto mode on,** but only by forging two steps on purpose: staging over the socket, then the confirm (`auto-confirm` with the staged id, or the GUI's confirm with the token from `gui.json`). No tool, single command, or event does it.
  - **Turn auto mode off** with one `tower-event` to the head carrying 我起床了, or one `auto` off over the socket. D9 puts no confirm on off. Agents would then ask a boss who is away, and those questions wait as they do today. Nothing is cancelled.
  - **Make the head misread** a matching line of the boss's: injected text cannot pass (the server reads only the boss's own event), but the model can call `boss_auto` against what the boss meant. For on, the confirm catches it.

  Every such act is recorded with its requester, notified to every pane, and listed on the return list.
- **The going-to-sleep skill (AM-W2).** Before the boss leaves, the skill hands them `/boss auto on` through `robot_hand` (`kind: pi`). Auto mode is still off then, so robot_hand still works. 「我要睡了」 said to the head tower goes to `boss_auto`.
- **Ending it (AM-W2, D2).**
  - 「我起床了」 said to the head tower ends it.
  - Said to a main, it does not. The skill's waking step tells the boss to type `/boss auto off` or flip the switch.
  - sb says the same once per session, on the boss's first typed input while auto mode is on (`ctx.ui.notify`): `Auto mode is on since 23:10: agents cannot ask you. /boss auto off ends it.`
- **No expiry** (D4).

### 3. What auto mode refuses

The guard is a new `src/auto.ts`, registered before the child return. It therefore holds in mains, members, trains, subagents, and the standing panes' hand runs. The table lists every installed source of a wait; a new extension is checked against it (AM-F003).

| Source | Boss wait | New call while on | Open when it turns on |
|---|---|---|---|
| rpiv-ask-user-question | `ask_user_question` | refused at `tool_call` | cancelled (the owner's cancel) |
| pi-code 1.7.0 | `question` (drawn with `ui.custom`, `extensions/question.ts:226`) | refused | the turn is aborted (§5) |
| pi-robot-hand | `robot_hand`, `secret_drop` | refused | cancelled. Version 0.6 and later take `cancel` (task 6); an older one gets the turn aborted |
| pi-straw-boss | `link_request` (an approval of up to 10 minutes) | refused | cancelled |
| pi-mcp-adapter | `mcp` with `action: auth-start` or `auth-complete` (a browser login) | refused | — (the call returns at once) |
| any extension, inside a model's tool call: `ctx.ui.select`, `confirm`, `input`, `editor` (pi-code hook confirms, mcp approvals and elicitation, pi-intercom `confirmSend`) | a confirm or a prompt | resolved at once as Escape (`undefined` or `false`) without drawing, and the call's result gains the tail of §4 | cancelled if relayed, else the turn is aborted |
| pi-straw-boss Straw Link | a remote turn's gate confirm | denied at once: `no one can confirm this here now` | denied |
| pi | the project trust question | answered `not trusted for this session` (D3) | answered so |

- **Inside a tool call only** (AM-F005, AM2-F002).
  - pi runs a typed extension command at once, even while a turn streams (pi 1.3.0 `agent-session.js:1609-1617`). Tool calls in flight (`flying`) therefore do not mean the dialog came from one of them.
  - sb runs its own `/boss` handlers inside an `AsyncLocalStorage` mark. The wrap answers as Escape only for a dialog opened while a tool call is in flight and outside that mark. The boss's own commands therefore draw their confirms (`/boss stop`, `send`, `close`, link writes), mid-turn too.
  - The transition skips dialogs opened under the mark.
  - Other extensions' commands typed during a running turn are not told apart (**Risks**).
- **Not refused:**
  - waits on an agent or an event: `call_tower`, `intercom` `ask`, `caller_ping`, `goal_wait`, `MonitorCreate`, `LoopCreate`;
  - a `subagent` spawn of any kind: a parent never waits on an interactive child (AM-F003; the earlier row is cut);
  - notices;
  - `show_doc` (D7). Its result gains `Auto mode: the boss sees this when they are back; do not wait for its form.`
- **A blocked `call_tower`.** The result of `call_tower` `why: blocked` gains: `Auto mode: no answer from the boss before it ends. Do not wait on this call: the tower parks it; go on with work that does not need it, or stop this line and say so on your board.`

### 4. What the agent is told, per kind

All of this is code-written, in English. `Refused:` and `Cancelled:` take the tail of the session's kind (AM-F015):

```
Refused:   sb: auto mode is on (since 23:10; the boss is away): <tool> waits for the boss and is refused. <tail>
Cancelled: sb: auto mode started at 23:10: this <tool> was cancelled by sb, not by the boss, who is away. <tail>
```

| Kind | `<tail>` (all open with "Do not ask again or wait.") |
|---|---|
| main, member | Decide yourself only where the boss's words in your brief or this session cover it, quoting them; else park it: `call_tower` `why: blocked` with the decision and what you need, then go on with work that does not need it, or stop this line and say so on your board. |
| subagent | Decide within your brief; else `caller_ping` your dispatcher with the decision and stop. |
| train | `call_tower` `blocked` with `reply: false` naming what needs the boss, then end. |
| workspace tower run, head run | Record a wait for the boss with `tower_memory`; it is parked. (Neither run has these dialog tools; the line is there for a hand run.) |

- **The secret line.** For `secret_drop`, the tail adds `Name the secret, never its value.`
- **Every tail ends** with `Only the boss or the head tower ends auto mode.`
- **A cancel never reads as the boss's Esc.** For a call sb cancelled, the `tool_result` handler replaces the result by the call's id.
- **An aborted turn** (AM-F004). After `ctx.abort()`, sb waits for `agent_settled`, then sends the text with `pi.sendMessage(msg, { triggerTurn: true })`. It uses the bridge's guarded captured context (`src/bridge.ts:304`).
- **The transition notice** goes to each session once, after the server's check (§1): a `steer` while a turn runs, `nextTurn` while idle, so it starts no turn. Its text: `sb: auto mode is on since 23:10: the boss is away until they end it. Nothing that waits for them runs; decide only where the boss's words cover it, or park it; never wait for the boss.`
  - Ally runs get no notice (D5, AM-F011).
  - No system prompt changes.
- **No kind prompt grows (D7 of agent-kinds).** `duty-standing.md` already sends questions to `call_tower` `why: blocked`, and under auto mode the tower parks them. This answers agent-kinds §9's note.

### 5. Cancelling what already waits: two layers

1. **In the session.** Once the server confirms the write, `auto.ts` takes the bridge's open dialogs (a new `bridge.cancelWaits()`) and ends those §3 lists:
   - an owner that takes a cancel gets the cancel;
   - the rest get the abort of §4.
   It notes each one to the server (`auto-note`: session, tool, at, and a gist of at most 120 characters: a question's header, a command's first line, a secret's label). A gist that looks secret-shaped (`secretShaped`) is stored as `(withheld)`. Refusals are noted the same way. A note that fails is dropped.
2. **On the server (the backstop),** for sessions on an older sb (AM-F009).
   - While auto mode is on, a unit whose `pending` dialog has been open for 30 s gets the GUI's cancel through the hub, if its `Answerable` has `cancel`.
   - Each dialog id is cancelled at most once, and paired with an intercom message to the unit that carries the `Cancelled:` text. A re-ask is listed, not cancelled again.
   - A dialog with no cancel is listed as `still waiting`.

### 6. Towers under auto mode

- **The run brief** of every workspace tower and the head gains one line, written by code:

  `Auto mode: on since 23:10 (the boss is away). A wait for the boss you record is parked and raises no alert. Answer a blocked call yourself only from your memory's standing instructions and decisions or a boss event you took; a sender's quote alone is not enough: record the wait and tell the sender with tower_reply to go on without it.`

- **`auto-decided` notes** (AM-F008, AM2-F004). While auto mode is on, the server notes every `tower_reply` and `tower_send` from a run to a session whose `blocked` `call_tower` event that run took (matched by the sender's broker id). Each note carries a 120-character gist.
  - Both tools gain an optional `basis`: a memory id (`S<n>`, `D<n>`) or the id of a boss event that is not a press. The server checks it against the memory and `runs.bossEvents`, and records `basis: none` when it is missing or fails.
  - The notes go on the return list.
- **Parked cards.** A wait card recorded while on gets `parked: true`. When auto mode turns on, the open boss waits get it too.
- **The raiser of a parked card** gets one message under a new header kind `wait_parked` (`src/header.ts`), not `wait_card`, which means "the boss's answer" (AM-F007). Its text: `Wait W9 is parked: the boss is away (auto mode). Do not wait on it; its answer comes as a wait_card message when they are back.`
- **A secret card's press is refused** while on, with `end auto mode first (/boss auto off)`, and its start button is hidden (AM-F013).
- **Approvals the boss has not given are refused, not waited for.** Examples are a `strict` target that a slip's `auth` does not cover, or a production go that the boss has not given.
  - The slip's sender cannot ask, so it parks the car.
  - The integrator asks no one, and a train ends after `blocked` (`prompts/train.md:14`).
  - sb adds no deploy gate. A deploy the boss authorized before auto mode runs as authorized.
- **With `towerRuns` off,** no tower records cards. The return list was meant to show the board lines changed during the period; that reader is **phase 2** (AMC-F007): in phase 1 nothing waits or is lost, but such a setup gets no board lines in the summary.
- **Amendment of the wait-cards spec** (its Out section left the alert queue as it was): parked cards are silent (D8, §7).

### 7. The GUI (mirrors)

- **The switch.** The header chip `自動模式 · 23:10 起` / `Auto · since 23:10` holds the switch of §2. On a phone it sits in the `⋯` drawer, with 44 px targets. Each theme restyles it as it restyles the header.
- **The head's confirm** (D9) is in phase 1 (§2): the button on the head page and the Zen strip, shown while a pending record lives.
- **Parked cards** read 「已暫放，等你回來」 / "Parked for your return". While on they raise no system notification, sound, or Zen cue, and stay out of the dock queue (D8).
- **Cut** (AM-F014): the head band chip, Zen's circle line, and the timeline events.

### 8. The end: the return list in one round

When auto mode ends by any door:

1. **The report.** The server writes `off` and builds `<state>/auto-report.json`, for the last period only. It holds:
   - `since`, `until`, and who switched it each way;
   - the parked waits per tower and the head;
   - the cancels and refusals per session (tool, count, first time, gist);
   - `auto-decided` replies;
   - `still waiting` dialogs;
   - the boxes' asks left waiting (D6);
   - foreign or unreadable writes.
2. **pi.** `/boss auto off` prints it: the parked waits by `W<n>` first, the rest folded by session. `/boss memory done|choose|decline W<n>` acts on them.
3. **GUI.** One panel opens on the next page load: the parked cards first, pressable, then the rest folded. Closing it leaves the cards as open waits.
4. **The head tower** gets one event: `Auto mode ended at 07:40 (<who>): <n> parked waits on <m> towers, <k> cancels or refusals.` When the boss said 「我起床了」 to it, it presents the list.
5. **Every session** gets one message (`steer` or `nextTurn`), once the server's check confirms the `off` (§1): `sb: auto mode ended at 07:40: the boss is back. Parked waits go to them in one list, and their answers reach you as wait_card messages; do not ask again what you parked.`
6. **`boss_status`** shows the state and the report's summary (read-only), for the going-to-sleep waking step.

### 9. Esc before a decline (normal mode, AM-W3; its own todo)

This ships under its own todo, independent of auto mode (AM-F014).

- **What counts** (AM-F006): a question the boss cancelled with no words.
  - `ask_user_question`: `details.cancelled` with no `details.error`.
  - `robot_hand`: `by: "cancel"`, read from robot-hand's `closed` event on the bus, keyed by `toolCallId`. "No, thanks" is `by: "local"` and counts as an explicit answer.
  - `secret_drop`: its cancel, unless the boss used the reply field.
- **The note.** sb's `tool_result` appends: `The boss cancelled with no answer; it may be a slipped Esc. Ask once more, saying it is the second time; a second cancel is a decline.`
- **The second cancel.** The decline line `Cancelled again: the boss declines; do not ask a third time.` is used only when all of these hold:
  - the session's next question is cancelled the same way;
  - no question was answered in between;
  - it comes within 10 minutes.
  Any answer resets it.
- **Under auto mode.** A cancel sb made is never the boss's: it gets the `Cancelled:` text and no note. A re-ask is refused, so the agent parks it.

### 10. Scope: this computer

- **Covered:** one computer, every Herdr slot on it.
- **Not covered:** a pi outside Herdr.
- **Teammates are not told** (D5). Gate denials say `no one can confirm this here now`, and ally runs get no notice.
- **An unattended device has no auto mode.** `/boss auto` there answers `an unattended device has no boss at it; its waits go to its controllers`.
- **A controller in auto mode** leaves its boxes' forwarded asks waiting, and lists them (D6). Listing them is **phase 2** (AMC-F006): the waiting holds by default, but the return list has no source for the boxes yet, so it says `not collected` and the boss looks at the page's waiting dialogs.
- **Operate sessions** cannot switch it on either end.

## Security

- **Only the boss's own act switches it** (§2):
  - a typed `/boss` command;
  - a GUI write, with the page token and CSRF; never a run token or an operate session;
  - the head's `boss_auto`, gated on a head token, the run's own report of the turn's starter (never a press), and the server's reading of the boss's own event text against a fixed list;
  - for on, from any door but the GUI's two taps, the boss's confirm of a pending record (D9). §2 says what a same-user process can still forge.
- **Fails safe.**
  - A foreign or unreadable file cancels nothing.
  - Refusals follow the file. They are reversible, and the server puts a foreign write back within 2 s.
  - A guard that throws refuses the call.
- **The residuals are today's.** A same-user process can write files, speak to the control socket, read `gui.json`, or type into a pane with `herdr pane send-text` (§2, "What remains possible"). Every switch and staging is notified to every pane and listed with its requester.
- **No secret on the list:** gists are capped at 120 characters, and a secret-shaped one is withheld.

## Acceptance

- [ ] **Doors.** Only `/boss auto`, the GUI switch, and the head's `boss_auto` change the state. The head's acts only on the boss's own matching words, never a press. On, from any door but the GUI's two taps, needs the confirm of a live pending record. A foreign write is put back, cancels nothing, and is listed. Every switch is notified and recorded with its requester.
- [ ] **Survives restarts.** The state stays as it was across a restart of the server, pi, Herdr, and a Mac sleep.
- [ ] **Refusals.** While on, every source row of §3 is refused or answered at once, in mains, members, trains, and subagents, with the kind's text. The boss's own commands still confirm.
- [ ] **Cancels.** In sessions on this build, open waits end within one poll after the server's check, each with sb's text, and an aborted agent goes on. Older sessions get the backstop where a cancel exists.
- [ ] **Waits are parked.** A wait card recorded while on is parked and silent, and its raiser gets `wait_parked`.
- [ ] **The end.** The return list appears once: in pi, in the GUI panel, and in the head's event. Sessions are told not to re-ask.
- [ ] **The Esc rule** (its own todo). The note and the decline line as §9 bounds them.

## Risks

- **Not covered:**
  - a pi outside Herdr;
  - a session on an older sb (backstop only);
  - another extension's `ui.custom` dialog, which can only be ended by aborting the turn, at the transition.
- **An abort costs the turn's other parallel calls.** Task 6 removes that for robot_hand and secret_drop.
- **Agents may decide more on their own.** The tails allow a decision only on the boss's quoted words, and the return list shows every refusal and every `auto-decided` reply.
- **The boss at the keyboard while auto mode is on** cannot be asked. The once-per-session notice says how to end it, and their own `/boss` commands still confirm. Another extension's command typed during a running turn may have its confirm answered as Escape (AM2-F002).
- **A forged off** (§2) brings questions back while the boss is away. They wait, as they do today, until the boss ends them or auto mode is on again.
- **The trust answer "no"** (D3) can make a child in a hand-made worktree fail, which is reported, instead of hanging until morning.
