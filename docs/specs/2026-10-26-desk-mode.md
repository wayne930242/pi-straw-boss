# Desk mode

Status: approved by the author 2026-10-26 with every recommendation in **Decisions**, D8 as amended there. S1 to S4 and S6 to S10 are built; S5 and S6's install are `cli.mjs up --dir` of the sb server (B7, docs/specs/2026-10-26-sb-backend.md, **Desk mode: what changes**), which replaces S1's tower start and the 90 s restore wait.
Base: pi-straw-boss 0.43.0 (`main` at `e78c08e`, Straw Link step 4 merged), pi 1.4.0, Herdr 0.9.5, pi-intercom 0.17.1.
Consumer: [straw-boss-desk](https://github.com/wayne930242/straw-boss-desk), whose design record (`docs/specs/2026-10-25-design.md`) and phase 0 spikes (`docs/spikes/mac.md`, `docs/spikes/windows.md`, `spike/win/RUNBOOK.md`) found the seams below.

## Intent

straw-boss-desk is an Electron app that installs Herdr, pi, and pi-straw-boss on a bare macOS or Windows machine, starts `herdr server` and one tower pi, and shows the straw-boss GUI in its window.
It must not reimplement pi-straw-boss, so today it drives the extension the way a person would: it mirrors `src/towertab.ts` with Herdr commands to make a tower, types `/boss gui` into it, and hides the browser that command opens behind an `open` shim.
On Windows the typed command was swallowed up to three times and the GUI took 85 s.

Desk mode is a supported way for such a shell to run the stack: the tower opens the GUI by itself with no browser, one command makes the shell's home base and its tower, and the files the shell reads are a documented contract.
Everything is switched on by the shell's environment and changes nothing for a machine that does not set it.

## Scope

- In: the seams S1 to S10 below, each with its interface, Windows and macOS details, tests, and acceptance; how desk mode meets a restored tower and Straw Link; the rollout and what the shell drops after each release.
- Out:
  - The shell's own work: its supervisor, wizard, preload script, and Herdr's configuration.
  - A GUI server that runs without a pi session (the spike's "headless GUI process"): the GUI keeps needing one live pi, and the shell keeps the tower alive.
  - Stopping the stack: the shell keeps `herdr server stop`; no desk command stops anything.
  - Herdr rebuilding a Windows pane's `PATH` from the registry, and pi downloading `fd` and `rg` on first start: reported to Herdr and handled by the shell's bootstrap.
  - Enforcing the hidden features: hiding is presentation only (S9).
  - The switchboard (one task-oriented main per machine) and the Straw Link GUI: specified separately; this spec only keeps room for them.
  - Linux as a desk platform (nothing here is macOS-only, but nothing is tested there).

## Reality anchor

- The GUI starts only from `/boss gui` (`host.command("")` in `src/host.ts`, which ends in `openUrl`), from the restore after a `/reload`, or from a survivor adopting a server whose owner died (`adopt` in `src/host.ts`).
  A fresh state directory has no record, so nothing adopts, and `/boss gui` is the only start.
- `openUrl` defaults to `openBrowser` (`src/gui.ts:216`: `open`, `cmd /c start`, or `xdg-open`); `Deps.openUrl` can replace it only through `createStrawBoss`, never from the environment.
- The state directory is `cfg.stateDir ?? $PI_CODING_AGENT_DIR/straw-boss` (`src/state.ts:115`), computed again for the sidecar (`src/agent/paths.ts:12`); `gui.json`, `roles/`, `stash/`, `link/`, and `config.json` all live there.
- A tower is a pi whose shell has `STRAW_BOSS_ROLE=tower` (`src/state.ts:99`), or whose session or role record says so (`src/session.ts:74`, `src/roles.ts`).
  `ensureTower` (`src/towertab.ts`) opens one in a workspace, reusing a marked or bare tower tab, and runs only inside a pi session.
- `gui.json` carries `started` only when `ps -o lstart=` answers (`startOf`, `src/remote.ts:172`).
  Windows has no `ps`, so a Windows record has no `started` and no survivor adopts it (`adoptable`, `src/handover.ts`), and the link holder's liveness (`holderAlive`, `src/link/election.ts:26`) and lock (`src/link/store.ts:123`) fall back to the PID alone.
- `gui.json` is written in place with `writeFileSync` (`src/handover.ts:51`, `:60`, `:168`), so a reader can catch half a file.
- `runHelper` (`src/balance.ts:14`) spawns `node` detached without `windowsHide`; on Windows a detached console child gets a console window of its own.
- A pane joins the net only when Herdr reports its `agent_session`, which only Herdr's pi integration (`herdr integration install pi`, writing `$PI_CODING_AGENT_DIR/extensions/herdr-agent-state.ts`) provides; without it a member stays out of the net with no message (mac spike, failure 1).
- The folder picker accepts only folders under the home folder outside hidden folders (`pickable`, `src/spawn.ts:31`); Windows hidden and system folders are being taken out on `fix/restored-opener-and-win-hidden`.
- The page shows the Phone button only on `127.0.0.1` (`gui/main.ts:202`), a Stash button on every base (`gui/render.ts:156`), and a Stashed list while something is stashed (`gui/quit.ts:47`).
- A Herdr restore resumes each pi pane into its session file with the same workspace, tab, and pane ids, and 0.43.0 gives a tower or main its role back from `roles/` (Windows spike: "pi-straw-boss 0.43.0 restores tower and main roles").

## The switch

`STRAW_BOSS_DESK=1` in the environment the shell starts `herdr server` with.
Every pane Herdr opens inherits it, so every pi on the stack (the tower, the mains and members the page opens, a pane a restore resumes) agrees on desk mode, and the session that hosts the GUI, whichever it is after a takeover, serves the desk page.
Any other value, or none, is normal mode.

Why the server's environment and not `config.json`: desk mode is a property of how the stack runs, not a user setting, and the shell already builds that environment (`PI_CODING_AGENT_DIR`, `HERDR_SOCKET_PATH`); a key in `config.json` would make the shell edit a file the extension also writes (`link`), and would outlive an uninstall of the shell (D1).

## Seams

### S1. The tower opens the GUI at its start

Required: in desk mode, a session that has just taken its workspace's tower role (`startTower` reached `s.holdsTower = true`) and has a UI ensures the GUI server, as `/boss gui` does, without opening anything.
The server that answers is reused; otherwise one starts, on the recorded port when there is a record (its GUI under the stored token, S4; D27).
A record marked `stopped` is started too: a desk tower starts only when the shell starts the stack or the stack restarts, which is the person opening the app (D4).
A tower that yields to a rival in its workspace starts nothing.
A failure is told in the tower's pane as a warning and reported by `desk up` (S5).

Interface: none beyond the switch; the call is `host.share()` from the tower branch of `session_start` (`src/session.ts:79`) after `startTower` resolves.
Every tower in desk mode does it, the home base's and any base's tower a promotion opens; when the server answers, it costs one lock and one GET.

Why at tower start and not at every session start: the tower is the long-lived session the shell keeps, the host election already prefers towers, and a member starting the server would only hand it to a tower later.

Tests: in the fake Herdr and broker harness, a tower with `STRAW_BOSS_DESK=1` writes `gui.json` and its server answers, with `openUrl` never called; the same tower without the switch starts no server; a second desk tower in another workspace reuses the first server (one record, same port); a `stopped` record is started; a tower that yields to a rival starts nothing; a restored tower (role from `roles/`, no `STRAW_BOSS_ROLE`) starts the server.
Acceptance (macOS, straw-boss-desk `spike/mac` kit with the packed release): `03-tower.sh` with neither typing nor a first message gets `gui.json` within 15 s of pi's start, five runs out of five.
Acceptance (Windows VM): five starts in a row, cold and warm, bring the GUI up with no command typed; a warm start answers within 15 s of the tower being ready.

### S2. No browser in desk mode

Required: in desk mode `/boss gui` prints the URL and opens nothing; the remote pairing overlay's **o** key does nothing.
Normal mode still opens the browser.

Interface: `createStrawBoss` uses a no-op `openUrl` when `env.STRAW_BOSS_DESK === "1"` and none was injected.

Tests: `/boss gui` in desk mode tells the URL and calls no opener; in normal mode it calls it once.
Acceptance (macOS): the kit's recording `open` shim records nothing over the S1 runs, then the shim is removed from the kit.

### S3. The state path

Required: the shell reads and owns one fixed directory.

Interface: no new variable.
The state directory stays `$PI_CODING_AGENT_DIR/straw-boss`, which the shell already fixes by setting `PI_CODING_AGENT_DIR` to its own agent directory; how-it-works documents that path, and the files a shell may read in it, as a contract (S4, S5).

Why not `STRAW_BOSS_STATE_DIR`: the directory must be the same for every pi, every sidecar, the sidebar plugin, and Straw Link, all of which derive it from `PI_CODING_AGENT_DIR` today; a second variable that a pane could miss would split one machine into two GUIs and two link holders, for no gain to a shell that already owns the agent directory (D2).

Tests: none new; the existing state tests cover `PI_CODING_AGENT_DIR`.

### S4. `gui.json` as the contract: ready and moved

Required: the shell can tell when the GUI is ready, when it went away, and when its URL changed, from the file alone.

Interface:
- The shell may read `port`, `token`, `pid`, `started`, `stopped`, `version`, `herdr`, and `owner` from `gui.json`; `csrf` and the rest are not for it, and the file is a secret (it holds the token), never logged.
  The URL is `http://127.0.0.1:<port>/<token>/` with the trailing slash.
- Ready: the record exists, is not `stopped`, and `GET <url>` answers 200, the check `answers` in `src/handover.ts` makes.
- Moved: the `token` changes only when a GUI listener starts with a new one, and the `port` changes too when a restart finds a recorded port taken; reload when `port` or `token` changes. Since D27 (the boss's choice, docs/specs/2026-10-26-sb-backend.md, **GUI token and CSRF secret**) a token outlives its listener: a server restart, a GUI restart, an upgrade, a start after a crash or an unclean exit, a reboot, and `/boss gui` after `/boss gui stop` write the record again with the same token and CSRF secret, on the same port when it is free, so the page the shell has loaded reconnects by itself. A new token comes with a taken port (the listener could not get both of its ports back), a missing, corrupt or stale `gui-secrets.json` (a hand-over from a 0.45 host is a new token: the older host never stored one, and a store from before it names another), and the boss's `/boss gui rotate`; the old token then answers 403, the shell must load the new URL, and both `gui.json` and `server.json` carry the new token before `restarting` is cleared. The risk of keeping it is another account binding the port in the gap between two servers and receiving what an open page sends (token in the path, CSRF secret in its requests); the boss accepted it. A paired phone keeps its pairing across a restart; a new token needs a QR scan again, because its cookie is scoped to `Path=/<token>/` (an installed app types the pairing code at the fixed entry).
  The shell watches the state directory (or reads the file every 2 s, the sessions' own cadence) and loads the new URL once it answers.
- Gone: the record does not answer; a survivor adopts within about 6 s (S7 on Windows), so the shell waits that long before it runs `desk up` again.
- Every write of `gui.json` goes to a temporary file in the same directory and is renamed into place (mode 600 kept), so a reader never sees half a file.
- No schema version: the shell pins the pi-straw-boss version in `stack.json`, so a change to these fields reaches it only with a pin it tests.

Tests: a reader racing 1000 writes (`writeRecord`, `markReload`, `markStopped`) never fails to parse; the file keeps mode 600 on macOS.
Acceptance: the shell's supervisor (phase 2) follows a takeover whose port was taken, without a restart of the app.

### S5. The home base and its tower: `desk up`

Required: one idempotent command makes the shell's home base and its tower, or finds them, and returns the GUI's URL once it answers.
It replaces the shell's copy of `src/towertab.ts` and its restore handling, which depend on internal tokens.

Interface:

```sh
node <agent dir>/npm/node_modules/pi-straw-boss/src/desk/cli.mjs up --dir <folder> --label <name> [--timeout <seconds>]
```

`cli.mjs` is plain JavaScript that registers the tsx loader found beside pi-intercom (as `src/agent/paths.ts` finds it for the sidecar) and imports the TypeScript, so the shell needs no loader path.
The shell runs it with the environment it gave `herdr server`; it refuses with exit 2 when `STRAW_BOSS_DESK` is not `1` there, which catches a shell that forgot the switch.

Steps, each named in a failure:
1. `herdr`: `herdr status` answers within 10 s.
2. `integration`: S6.
3. `base`: `desk.json` in the state directory names the home workspace (`{workspace, dir, label}`); while Herdr lists that workspace it is used, whatever its label is now.
   Otherwise the command creates one in `--dir` with `--label`, its first tab labelled as a tower tab and its root pane's shell given `STRAW_BOSS_ROLE=tower` and marked `sb_role=tower`, so the base has no stray shell tab, and records it (temporary file and rename).
4. `tower`: when the workspace has a live tower, it is used.
   When it holds pi panes that have not published a role yet (a Herdr restore resuming them), the command waits for them up to 90 s, so it never opens a second tower beside a restored one.
   Then it calls `ensureTower` for the workspace, with liveness taken from Herdr (the workspace's `tower` token and a pane marked `sb_role=tower` running pi), since the command is no intercom session.
5. `gui`: it waits until `gui.json` is ready (S4), up to `--timeout` (default 120 s; a cold Windows tower took 66 s).

Output: one JSON line on stdout, `{"url", "guiJson", "workspace", "pane", "tower", "created", "integration"}`; `created` says whether this run made the base or the tower.
Exit 0 on success; 1 with one JSON line `{"step", "reason"}` on stderr, where a `gui` failure includes the last 20 lines of the tower's pane (`herdr pane read`); 2 for usage.
A second `up` while one runs exits 1 at step `base` with "busy" (`desk.lock`, taken like `server.lock` and over after 10 minutes or from a dead holder; on Windows a reused live pid holds it until the 10 minutes are up, since the start time is not known within a short `up`).

Why a command in the package and not a documented Herdr sequence: the sequence is the internal contract (`STRAW_BOSS_ROLE`, `sb_role`, the tower tab glyph, the restore wait), and freezing it for an outside caller would make every change to it a breaking change; the command keeps it inside one release (D3).

Tests (fake Herdr): a fresh run creates one workspace with one tab, starts pi there with the tower environment, writes `desk.json`, and prints `created: true`; a second run creates nothing and prints the same workspace; a recorded workspace that is gone is created again; a workspace whose pi panes have no role yet is waited for, and a tower that publishes meanwhile is used; no tower within the budget opens one; no GUI within `--timeout` exits 1 at `gui` with the pane's lines; a missing switch exits 2.
Acceptance (macOS kit and Windows VM): from a fresh agent directory `up` prints `created: true` and the URL answers; a second run prints `created: false` and opens no tab; after `herdr server stop` and a new server, `up` returns without a new tab and the tower is the restored one.

### S6. Herdr's pi integration

Required: a member that cannot join for want of the integration says so, in every mode; in desk mode the integration is in place before the tower starts.

Interface:
- Every session, once 20 s after its start, reads its own pane; when Herdr reports an agent but no `agent_session`, it warns once per process: Herdr's pi integration is missing for this agent directory, so this session cannot join the net; run `herdr integration install pi` and restart pi.
- `desk up` reads `herdr integration status` and runs `herdr integration install pi` unless the `pi:` line says `current`; its output reports `current` or `installed`.
  An outdated integration is installed again the same way, so a Herdr update brings it along.
  Herdr's status has no JSON, so the check is that one line; misreading it costs one extra install, which is idempotent.

Why install in `desk up` and not only warn: in desk mode the agent directory is the shell's own, so writing to its `extensions/` touches nothing of the user's, and keeping the step there spares the shell a bootstrap stage of its own (D5).
Normal mode never installs anything.

Tests: a session whose pane lacks `agent_session` warns once after the grace and never again; one with it does not warn; `desk up` installs when the status line is `not installed` or `outdated` and not when it is `current`.
Acceptance: with the integration uninstalled, `desk up` prints `installed`, and a member opened from the page joins the net.

### S7. A process's start time on Windows

Required: `startOf` answers on Windows, so `gui.json`, `remote.json`, and the link holder's record carry `started`, and a survivor adopts the GUI there as on macOS.

Interface: on `win32`, `startOf(pid)` runs `powershell.exe -NoProfile -NonInteractive -Command "(Get-Process -Id <pid> -ErrorAction Stop).StartTime.ToUniversalTime().ToString('yyyy-MM-ddTHH:mm:ss.fffZ')"` with `windowsHide` and a 5 s timeout, asynchronously, never on the event loop's critical path. This process's own start time is read once in the background when the session starts and kept for its life; another PID's answer is cached by PID. A record written before the own start time is known is written again when it arrives.
`runs` parses that ISO text as it is (it appends ` UTC` only to the `ps` form).
macOS and Linux keep `ps`.

Why PowerShell, asynchronously: Node has no API for another process's start time, `wmic` is no longer installed by default on current Windows 11, and both sides of every comparison read through the same function, so the text needs only to be stable, not to match `ps`. One PowerShell call took 1.9 to 2.8 s in the Windows 11 ARM VM (2026-10-26), so a synchronous call would stall the session at start and every 30 s in `holderAlive`; callers await the answer instead.

Compatibility: this changes normal Windows use too: a survivor now adopts a GUI whose owner died, and the "could not read its own start time" warning goes away.

Tests: unit, with the command injected: the arguments, `windowsHide`, the timeout, a parse of its output, undefined on failure; `runs` with the ISO form, with and without a recorded `started`.
Windows CI (`tests/platform.test.ts`): `startOf(process.pid)` is defined and the same on two calls; a written record has `started`.
Acceptance (Windows VM): closing the tower's tab while a member lives leaves a GUI answering within 6 s (on the same port, under the same token, which the shell's page reconnects to); no session start or `holderAlive` tick waits on PowerShell (the start of the tower is not slower than without S7).

### S8. No console window from the pane balance

Required: `runHelper` hides the console of the detached `node` it starts.

Interface: `windowsHide: true` in its spawn options, as `src/closing.ts` and `src/agent/cli.ts` already have.

Tests: the injected launch receives `windowsHide: true`.
Acceptance (Windows VM): opening a base from the page shows no console window on the desktop.

### S9. Hidden advanced features

Required: in desk mode the page hides GUI remote access (the HUD's Phone button and its tile) and stash (each base's Stash button and the HUD's Stashed list).
The server's routes stay as they are: hiding keeps a PM's screen simple and makes no security claim, since the URL is the credential either way.
Straw Link's GUI, when it ships, is not hidden: it is how a desk joins a team.

Interface: the server adds `<meta name="sb-desk" content="1">` beside `sb-csrf` when the hosting session runs in desk mode; the page reads it once at load.
A fixed set, not a list the shell passes (D6).

Tests: the served page has the meta only in desk mode; with it, the page's pure render leaves the Phone button, the Stash buttons, and the Stashed list out; without it, nothing changes.
Acceptance: a capture of the desk window shows neither button, also after a member took the server over.

### S10. Folder picking through the native dialog

Required: in the desk window the folder steps (new base, new main, and later Straw Link's project folder) offer the operating system's folder dialog; a browser keeps the page's own picker only.

Interface: the shell's preload exposes `globalThis.strawBossDesk = { pickFolder({ defaultPath, title }): Promise<string | null> }` through `contextBridge`.
When it exists, `gui/picker.ts` shows a **Choose…** button that opens it at the picker's current folder; a chosen path is listed through the existing `POST api/dirs {path}`, so the picker moves there and the person confirms as before.
The server's checks do not change: a folder outside home, or under a hidden folder, is refused with the message the picker already shows.

Why through the in-page picker: the server stays the one judge of a folder, and the page needs one call and one button, not a second flow.
Whether desk mode also allows folders outside home (another drive on Windows) is D7.

Tests: with a fake hook, a chosen folder is listed and selected; `null` changes nothing; a refused path shows the refusal; without the hook the button is absent.
Acceptance (both platforms, phase 2 shell): "+ New base" through the native dialog opens a base in a folder under Documents.

## A restored tower

- The shell starts every `herdr server` with the switch, so a pane a restore resumes has it although it lost `STRAW_BOSS_ROLE`; the tower takes its role back from `roles/` (0.43.0) and S1 runs for it as for a new tower.
- On macOS a member may adopt the GUI first (a tower at its first look, 2 s); the restored tower's S1 then finds the server answering and reuses it.
  On Windows the same holds once S7 ships; before it, S1 is what brings the GUI back.
- `desk up` after a restart waits for the home base's resumed panes (S5 step 4) instead of opening a tower beside the restored one, and finds the home base by its workspace id, which a restore keeps (an id can come back for another workspace after a restart, so it counts only while the workspace still has a tower tab or a pane in the recorded folder; sb-backend, Desk mode: what changes).
- A tower the person closed (the tower card's close button) has dropped its role record, so the next `desk up` opens a new one in the home base; a home base the person quit is created again.
- Taking over the mains a restored tower had opened is fixed separately (`fix/restored-opener-and-win-hidden`) and needs nothing here.

## Straw Link

The resident tower is the machine's link holder (Straw Link spec, **Link holder**: "one long-lived tower is the only candidate, as in straw-boss-desk").
Desk mode keeps that true:

- It adds no state directory (S3), so `link/` stays beside `gui.json` and every candidate reads the same `holder.json`.
- The home tower is an ordinary tower: a candidate at its first look, as before.
- S7 gives the holder's record and lock a start time on Windows, so a PID reused after a crash is no longer taken for the holder there.
- S9 hides nothing of Straw Link, and S10's hook serves its project folder step too.
- Delivery goes to a tower whose cwd is inside a team's project, so the home tower, which works in the shell's own folder, holds the link but takes no team's messages; with no project base open they wait in the inbox as the Straw Link spec says, until the switchboard opens one.

## Compatibility

Without `STRAW_BOSS_DESK=1` nothing changes but three things every platform gets: `gui.json` is written by rename (S4), the extension warns about a missing pi integration (S6), and Windows has start times (S7), which turns on GUI adoption and a stricter link holder check there.
`desk up` is a new command and touches nothing until run.
A record written by an older build stays readable, and an older build reads the new one, since the fields do not change.

## Notes for the shell

- Put the home base in a visible folder under home (for example `~/Straw Boss`), not under `%LOCALAPPDATA%` or `~/Library`: a hidden base folder is not pickable, so the page's folder steps in that base would start at home.
- Start `herdr server` and `desk up` with a constructed environment (`env -i` on macOS), never an inherited one: a `PI_SUBAGENT_ID` or `PI_INTERCOM_SESSION_ID` from a pi shell makes every pane act as a subagent, and the extension then stays inactive.
- Keep recording the PIDs it starts and stopping with `herdr server stop`.

## Rollout

Each release bumps the pin in straw-boss-desk's `stack.json`; the right column is what `spike/win/start.ps1` (and the macOS kit) can drop once it is pinned.

| Release | Seams | The shell drops |
|---|---|---|
| R1, 0.43.x patch | S4 (rename, documented contract), S7, S8 | Nothing from `start.ps1`; the supervisor can count on a survivor adopting the GUI on Windows while a member lives. |
| R2, 0.44.0 | the switch, S1, S2, S6 warning, S9 | Step 3's `/boss gui` prompt loop (three sends, `$GuiTimeoutSec / 3` each), keeping only the wait for `gui.json`; the macOS `open` shim and `TOWER_OPEN=arg`. |
| R3, 0.45.0 | S5, S6 install | All of step 2 (the restore wait on `agent list` and workspace tokens, tower detection by `sb_role`, closing duplicate towers, `workspace create --env STRAW_BOSS_ROLE=tower`, `herdr agent start`), the `gui.json` wait, and bootstrap's integration stage. `start.ps1` becomes: start `herdr server` with the switch, run `desk up`, record PIDs. |
| R4, 0.46.0 | S10 | Nothing; the shell adds its preload. |

R1 is independent and can ship at once.
R3 needs R2, since `desk up` waits for the tower to start the GUI.
R4 can wait for phase 2 of the shell, which brings the preload.
Each release passes `npm run check` and `npm test`, its unit tests above, and its live acceptance on the macOS kit and the Windows VM before the pin moves.
Each also updates `docs/how-it-works.md`: S7 in **Windows**, the rest in a new **Desk mode** section that states the contract of S3 to S5, and the README's command table for `desk up`.

## Decisions

The author accepted every recommendation on 2026-10-26; D8 is amended: asynchronous and cached, as S7 now states.

| # | Decision | Recommendation |
|---|---|---|
| D1 | How desk mode is switched on | `STRAW_BOSS_DESK=1` in `herdr server`'s environment, not a `config.json` key (see **The switch**). |
| D2 | A state directory variable | None: document `$PI_CODING_AGENT_DIR/straw-boss/`; a second variable risks two GUIs and two link holders on one machine (S3). |
| D3 | How the shell makes its base and tower | The `desk up` command in the package, not a documented Herdr sequence (S5). |
| D4 | Whether a desk tower starts a GUI stopped on purpose | Yes: a desk tower starts when the app starts, which is the person opening it; `/boss gui stop` then lasts until the next start (S1). |
| D5 | Who installs Herdr's pi integration | `desk up` installs it when it is not current; every mode warns when it is missing (S6). |
| D6 | Which features desk mode hides | A fixed set, GUI remote access and stash, rather than a list the shell passes; routes stay (S9). |
| D7 | Folders outside home in desk mode | Not in v1: the native dialog feeds the in-page picker and the home-only rule stays; a list of extra roots (another drive) waits for a PM who needs it (S10). |
| D8 | Windows start times | PowerShell `Get-Process`, asynchronous: this process's own start time read once in the background and kept, other PIDs cached; nothing waits on it at start (S7, amended after a 2 to 3 s call was measured in the VM). |
| D9 | Whether S10 ships in v1 | Ship it with phase 2 of the shell (R4); the in-page picker already works on both platforms, so nothing waits on it. |
