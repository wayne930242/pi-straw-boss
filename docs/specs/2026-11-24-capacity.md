## Decisions (boss, 2026-11-24)

| # | Question | Decision |
|---|---|---|
| Points | How a task is weighed | The box rule, kept on the todo as `metadata.points` (backend 2, frontend 1, no compile 0.5). A task with no points that a running worker owns counts 1. sb adds the points up and knows no weights. |
| Budget | Each device's budget | `capacity.budget` in `config.json`, with no default: a box measures, reports, and the boss settles the figure. Unset, the numbers show and nothing is flagged under capacity. |
| Stale | How long "work in hand, nothing moving" is | 30 minutes on an unattended device, for a main that runs nothing; elsewhere the board's 2-hour rule stays. |
| Quota | What a quota stop does | Wait for the reset (weekly limits too); the board shows when it resumes. |

## The problem

On 2026-11-24 box 2 ran at a load of 0.24 on 32 cores with an empty CI queue, each train carried one car, a main sat idle for hours waiting for the next car, and box 1 had been silent for about two days: a weekly Claude limit stopped its main and its tower runs, its board stopped 14 hours earlier, and it then dropped off the remote list without anyone noticing. sb could not see any of it: a board row had `now`, its items and a done count, but no points, no budget, no load and no quota state, and `stale` marked only an idle main whose line was 2 hours old, never one that commands work or stands.

## Design

### Who writes what

- **A main's own session** (`src/capfill.ts`) writes `<state dir>/capacity/<session>.json` from its todo list and its pause, whenever either moves: the in-progress todos that name an `owner` (`doing`), the pending todos whose `blockedBy` are all done or deleted (`ready`), the open count, and the pause. It reads the todo list through `todo.ts` and `items.ts` like the board's auto-fill (`todosOf` now keeps `owner`, `blockedBy`, and `metadata.points`), so the coming move to the todo contract changes one reader. The file sits beside the board folder, not in it, so the board's listing, purge, and tests are untouched.
- **The primary sb server** (`server/capwatch.ts`, `server/capops.ts`), with no model, once a minute: reads pi-intercom's list and Herdr's panes, joins each main's file with the subagents of its pane that run now (the dashboard's own reading, `subagentsOfAll`), and writes the device row `capacity/_device.json`. Only the primary server runs it, as the link holder: the mains of a second Herdr slot on the same computer are not counted.

### The join (`src/capacity.ts`, `joinCaps`)

- A main's points: each `doing` todo whose owner is one of its running subagents (or a live train) counts its points, 1 when it names none; each running subagent that no such todo names counts 1. The main itself counts nothing (the box rule). A live train that no main's todo names counts 1 at the device. Owner and worker names match case- and space-folded.
- Ready: the `ready` todos whose owner does not run; the smallest of their points is what a free slot must fit.
- The row also carries the 1-minute load average and the core count (`os.loadavg`, `os.availableParallelism`; Windows has no load average and reads 0), `capacity.budget`, whether the device is unattended (the link holder's word), and each main's numbers, pause, and stale mark.

The unmatched-worker rule is wider than the plan's wording ("sum over its in-progress todos whose owner is a running subagent"): without it a main that names no owners would read 0 points while its workers run, and the under-capacity flag would ask a tower to dispatch onto a full machine. A reviewer or scout subagent therefore counts 1 while it runs.

### The pause seam (shared contract with pi-agent-basic)

`pi.events` channel `straw-boss:pause`, payload `{ v: 1, state: "paused" | "resumed", reason: "quota", until?: number /* epoch ms */, detail?: string /* at most 120 characters */ }`, emitted in the session that stopped. sb imports nothing of basic and checks the payload field by field (`pauseOf`); any other version, state, or reason is ignored. The pause is cleared by `resumed` or by the session's next `turn_start`, kept across a `/reload` (read back from the file), and gone with the session's quit.

### Flags

| Flag | Rule | Where judged |
|---|---|---|
| `under` | Budget set, points plus the smallest ready todo within it, load under 0.7 per core; held 10 minutes. | The device row (`roomFor`, `underFor`). |
| `stale` | Unattended device: open todos, nothing running (no running subagent or train, points in use 0: a main commanding work is never stale), session file and board entry both unmoved over 30 minutes, any state, not paused. Elsewhere: idle, commanding nothing, not standing, entry over 2 hours old, not paused. | Per main (`staleOf`); where the row is read it replaces the board's own mark. |
| `quota` | Paused. | Per main. |
| `device-silent` | An ally device whose last board had open work, and that is offline, or whose board (when it carries capacity) is over 30 minutes old. | The receiving side, from the boards the link holder keeps (`allySeen`), however old. |

An older build's board carries no capacity and comes once an hour unchanged, so only its going offline counts.

### Events

Entering a flag is one event: a notice in the queue of the tower that hears of the main's workspace (`stallTarget`, as the stall watch; the head tower for an ally device), and one `kind=capacity_notice` intercom message from the server to this device's standing main, when there is one other than the main itself. `under` is told for each main whose smallest ready todo fits; `stale` only for a main with open todos. The same flag of the same main or device is told at most once per 30 minutes (a quota pause whose resume time differs is another flag, told at once); the marks are kept in `capacity/_sent.json` so a server restart does not repeat them. Nothing is said when a flag clears, except a quota that resumed while its main still runs. An event nobody took (no tower service, no standing main) is not marked and is tried again at the next tick.

Texts are terse and code-written: `capacity under · main "api" · 2 ready (smallest 1 pt) · capacity 2 / 4 pts · load 0.2 / 8 cores · ready 2 · under 10 min · held 10 min`, `capacity stale · main "api" · 2 open todos · …`, `capacity quota · main "api" · quota · resumes 16:02 · <detail>`, `capacity quota resumed · main "api"`, `capacity device-silent · device "box 1" (d1) · last board 31 min ago · offline · its last board had open work`.

A device still silent 2 hours after its first `device-silent` notice was told is escalated once (review prompts-review F003): `capacity device-silent-2h · device "box 1" (d1) · still silent 2 h after the first notice at 14:02 · last board 151 min ago · offline · needs the boss`, routed as the first notice (the head tower, and this device's standing main). The first notice's time and the escalation are kept in `_sent.json` while the silence lasts, outside the 30-minute throttle, so a restart neither repeats nor loses it; a device no longer flagged ends the silence, and a new one is noticed and escalated anew. An escalation nobody took is tried again at the next look. The 2 hours are sb's: no prompt keeps a timer of its own.

### Where it shows

- `board_read`: each `local` row gets `points`, `ready`, and `paused` (`quota · resumes HH:MM`); section `capacity` has the device's numbers, `underMinutes`, the paused mains among the rows the reader sees, and `secondsAgo`. A row over 5 minutes old is no reading, and the board's own stale rule stands then.
- `/boss board`: the device line under the head, and the numbers on each row.
- The head page: the board fold carries the device's numbers, each row its own (`gui/board.ts` `capText`, `rowCapText`; both languages).
- Allies: the `board` message's second field (`WireCap`), below.

### On the wire

`Board` gains an optional second field: `at`, `points`, `budget?`, `load1`, `cores`, `ready`, `minReady?`, `open` (fractions in hundredths), and the paused mains by the wire ids of the entries that team already gets, with `until`. No name, session id, path, or detail crosses. An older decoder takes exactly one field, so the holder adds it only when every other device on the team's roster lists `board.capacity` in a fresh `caps` (a new entry of `CAPS_FEATURES`); otherwise the board goes as before. The send hash leaves out `at` and the load, and a board that carries capacity is refreshed at least every 10 minutes (an hour before), so a receiver can tell a silent device from a quiet one.

## Limits

- The points are as good as the todos: a main that never sets `owner` is counted 1 per running subagent, whatever its weight.
- A subagent's name and a todo's owner are matched by name; a pane label that differs from the name the main used counts as an unmatched worker (1).
- Only the primary server's Herdr slot is counted.

## The cap

With `capacity.budget` set, the device's points gate a `worker` subagent instead of the per-main count of 4 (`src/workercap.ts`, `deviceRoom`): a worker starts while the points in use (the device row, under 5 minutes old), the device's live reservations, and the new one's weight fit the budget. Scouts, planners, reviewers, and watchdogs pass as before. With no budget, or no fresh device row, the count of 4 per main stands.

Admission is device-wide (review prompts-review F001: the row is sampled once a minute and usable for 5, so one row let six launches of one main through across turns, and a second main's too). Each admitted launch writes a reservation, `<state dir>/capacity/_reserved/<id>.json` (`src/capres.ts`; one file each, written under a temporary name and renamed), naming its main's session and the worker's folded `name`, and only then reads the device row and the sum, in the same admission; so every main's session sees it, two that launch at once both count each other, and a row the server wrote meanwhile is the one it decides on. A refused launch removes its own.

The device row lists, per main session, the running workers it sampled (`MainRow.workers`, folded; in the local `_device.json` only, never on the wire). A reservation stops counting for a reader only when the row that reader holds shows that launch: it lists the reservation's main session with a running worker of its name, and was sampled after the launch returned. That reader marks the reservation `seen` with the row's sampling time, and a later reader whose row is no older does not count it either (the worker is in that row's points, or it has ended); a reader whose row is older still counts it. No timestamp alone retires a reservation (re-review of F001: a reader of a lagging row counted nothing for a launch a newer row had retired for another reader, and over-admitted). Otherwise a reservation goes when its tool call fails or its turn ends without a result (blocked by another extension), at once, or 10 minutes after its launch (`RES_EXPIRE_MS`): the server stopped, the worker never showed, it carried no name, or it ended between two rows.

Only a main the device row lists takes this path. The server samples the mains of its own Herdr slot, so a main of a second slot, or one not sampled yet, keeps the per-main count of 4 and writes no reservation (a newer row could never show its workers).

Admission: device points + counted reservations + this launch ≤ budget. A row that shows a worker whose reservation a reader with an older row still counts holds it twice for that reader; that double count only delays its next launch.

The weight is that of the board's headroom (review F002: `roomFor` weighs the ready todo's points, admission counted 1 per worker): the `metadata.points` of the main's own open todo whose `owner` is the subagent's `name`, case- and space-folded as the join matches them (`nameKey`), read from its todo list as `capfill.ts` reads it; an in-progress todo before a pending one, 1 when none names it.

## Prompts

Plan section E, measured against the word budgets in `tests/prompts.test.ts`:

- `main.md`: dispatch up to the capacity budget (4 workers with none); an idle main dispatches its ready todos, else takes its next eligible work or reports idle; a capacity notice on its work is its own.
- `planning.md`: parallel up to the budget, serialize only on a real dependency or shared files; `metadata.points` weighs a task (default 1).
- `duty-standing.md`: capacity notices (`under`, `stale`, `quota`, `device-silent`) are incidents the standing main acts on; `device-silent-2h` goes to the boss with `call_tower` `why: blocked`.
- `tower.md`, `tower-run.md`: a capacity notice is an incident routed to the owning main; a dead main is revived; quota waits; a silent ally goes to its tower, and sb's `device-silent-2h` to the boss (a wait for him).
- `head-run.md`: a `device-silent` notice reaches the head tower, since an ally device has no workspace; the head sends it with `tower_send` to the tower of the workspace whose mains work with that device (`board_read` remote shows teams and devices), else records a wait for the boss; `device-silent-2h` is a wait for the boss (review F003).
- `integrator.md`: depart with 2 or 3 cars that share no files; a lone car waits only while another is due within `maxWaitMin`; a red gate drops the car that broke it; never skip a gate (boss 2026-11-24 「兩個都做」).
