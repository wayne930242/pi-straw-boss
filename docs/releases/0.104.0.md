# pi-straw-boss 0.104.0

Released 2026-11-26. A minor release on [0.103.0](0.103.0.md).

## Added

- **The doctor: `sb_doctor`, `/boss doctor [fix]`, and `cli.mjs doctor --session`.** When a tool an agent needs seems gone (`subagent`, `intercom`, `todo`, `MonitorCreate`), the doctor says which fault it is: **H1**, its package loaded nothing in this process (hand over to a fresh session, since a `/reload` does not cure what a process keeps); **H2**, it is registered and an extension left it inactive (`/boss doctor fix` makes it active again); a **stale** load, where the process runs an older pi-herdr-agents or pi than the one installed. **H3**, active in pi but not shown by the provider, is a note to call the tool directly, since nothing inside pi can tell it. Each role expects the tools of the packages its settings name; a child's `PI_DENY_TOOLS` is honoured. It reads pi-herdr-agents's load stamp, which that package writes from its `weihung/v3-integration` build 67a0d75 on. See [The doctor](../how-it-works.md#the-doctor).
- **A self-check at each session start.** At the first turn after a startup, `/reload`, new, resume or fork, every session in a pane, a child too, checks its expected tools once; when one is missing it shows a warning and adds one message to that turn, saying not to route around it with plain panes and to run `sb_doctor` and hand over.
- **`cli.mjs doctor --session <id|prefix|pane> [--json]`** checks another session from outside it: a fresh load of the same folder and settings by pi's own loader (its errors are pi's), the expected tools its session file was refused ("No such tool available") after its pi started, and that start against when pi-herdr-agents was installed. A tool the fresh load has and the session was refused is `H1-or-H3`. Exit 0 when healthy, 1 on a fault.
- `sb_doctor` is 260 characters and registered at the join, as the other net tools: a main, member, train and tower each carry +260; a session off the net and a child get the self-check and no tool (+0).
