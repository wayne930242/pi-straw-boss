# pi-straw-boss 0.115.2

Released 2026-11-28. A patch release on [0.115.1](0.115.1.md).

## Fixed

- **A milestone's hold follows the clock.** When the timer of a tower's milestone hold (D19) fires, the hold is read off the clock, as a wake held by the boss's answering already was: a timer that fires early is set again, and no run starts before the hold ends. Before, the timer's end started the run.
- 里程碑的等待以時鐘為準。塔台里程碑等待（D19）的計時器觸發時，會先看時鐘確認等待是否結束，和老闆回答時被擋住的喚醒原本的做法一樣：計時器提早觸發就重新設定，等待結束前不會開始 run。先前是計時器一到就開始 run。
- **`server.log` says when a restart waits for a supervisor.** A requester that waits for the supervisor to start a `serve` server again writes a `restart-supervisor-wait` line with who asked, the old pid, and the wait's budget.
- `server.log` 會記下重啟在等 supervisor。請求端在等 supervisor 重新啟動 `serve` server 時，會寫一行 `restart-supervisor-wait`，記下發出請求的人、舊的 pid 與這次等待的時限。
- **Test only.** More tests that failed only on a loaded machine now pass there. The boss-in-a-run tests and the D19 hold tests move a clock of their own instead of polling windows of the machine's time. The page-close stop test keeps answering the box's asks until the main has left. The seat test waits for pi's start itself, not the log line before it. The serve-restart test starts the supervisor's server once the second requester waits for it, not after a fixed time.
- 僅測試。又一批只在機器負載高時才失敗的測試，現在負載高時也會通過。「老闆在 run 裡」的測試與 D19 等待的測試改用測試自己推進的時鐘，不再輪詢機器時間的時間窗。頁面關閉的停止測試會持續回應 box 的詢問，直到主代理離開。seat 測試直接等 pi 在 pane 裡啟動，不再只等它之前的那行 log。serve 重啟測試等第二個請求端開始等 supervisor 之後才啟動 supervisor 的 server，不再等固定時間。
