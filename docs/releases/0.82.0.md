# pi-straw-boss 0.82.0

Unreleased. A minor release on [0.81.7](0.81.7.md).

## A tower revives a dead main

- **A main that dies comes back as itself.** The boss asked for it on 2026-11-23: 「是要讓塔台救」 and 「他的 agent type 也得一併回覆…也要回覆他在 sb 的 role」. A crash, a `kill -9`, or a pane or tab closed in Herdr runs no pi shutdown. A probe on 2026-11-23 showed that a Herdr close looks like a crash, not a quit. Its role record stays behind, and the sb server's tower now finds it: two looks a minute apart, outside Herdr's recovery window, raise one `main_died` notice per death. The tower run decides with the new `boss_revive_main`. It reopens the same pi session in a new tab, with the same intercom id, so the main gets back its role, kind, name, board row, todos, the replies towers expect from it, its link waits, and its wait cards. Its first message says what did not come back (monitors, loops, watches) and lists the waits and the missed messages it holds. The old tab is closed only when the tower opened it and it holds nothing but the dead pane at a bare shell.
- **What a revive refuses, with the reason:** a member (resume it with `pi --session`), a tower (it comes back by itself), a main opened for a teammate's device, a session something still runs, a file that is not a pi session of this workspace, a sender or workspace at its opened-main cap, an integrator while integration is off or its project has one, a death already tried once, a session whose revive failed in the last 24 h, a main that handed over, and a third revive in 24 h. A dead main's own old pane, and any pane whose pi is gone, count for no cap, though a dead pi's tokens live up to 10 minutes.
- **A train comes back as the same train** when its trainboard is still under way and its writer is gone.
- **The revived main picks up its own subagents.** Results nobody received (a finished run, a request for help) reach it in one message, framed line by line so the child's text cannot pass for Straw Boss's. Runs that were cut off are listed for `subagent_resume`, running ones are watched until they finish, and worktree runs and persistent specialists are listed without a resume. `subagent_resume` is refused for a session file a live pane runs.
- Design: [tower-revive](../specs/2026-11-23-tower-revive.md). Guide: [Reviving a dead main](../how-it-works.md#reviving-a-dead-main).

## A main opens its own successor

- **`boss_handover {handoff, reason}`**: a main that rotates its session opens its successor itself, with no `/new` and nothing for the boss to do. The boss: 「main agent 現在的交接都要叫我 /new，明明就有 herdr cli 可以用」. It goes through the same safe start as `boss_open_main`: a new tab in the main's workspace, a pi under its name and kind whose first prompt is the handoff file, and a note telling the successor to report to the old main. Only one live successor at a time. Refused for a member, a train, a tower, a main opened for a teammate's device, and in a teammate's turn. A main that handed over is never raised as dead or revived. See [A main's own handover](../how-it-works.md#a-mains-own-handover).
