# pi-straw-boss 0.109.1

Released 2026-11-27. A patch release on [0.109.0](0.109.0.md).

## Fixed

- **A closed lid no longer parks a tower's event.** A tower run's 20-minute cap was counted on the wall clock, so the time a Mac slept with a run live counted as the run's: a `wakeAfter` timer that came due in a dark wake started a run, the lid stayed closed, and at the next wake the run was timed out; a second run went the same way, and the event was parked after "two runs crashed with it" for the boss to retry or drop. The server now takes a gap between its watch's ticks (more than 30 s from the end of one to the start of the next) for time it did not run through, and gives it back to every live run: the cap, the idle and the boss's silence, the wrap-up grace, and the waits after a quit count awake time only. Such a run is neither timed out nor charged a crash, and a run that really runs past its cap awake still times out and counts. Local, head, ally, and conversation runs share the rule. No Node clock could do it: on macOS `process.hrtime` and `performance.now` run on through a sleep. See [Local runs](../how-it-works.md#local-runs).
- **A worker idle when the lid closed is not stopped at the wake.** The box's worker sweep stops a worker idle 60 minutes without its report; a sweep more than 5 minutes after the last now moves that idle clock on by the gap, so only awake idle time counts.
