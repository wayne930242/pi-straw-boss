# pi-straw-boss 0.81.7

Released 2026-11-21. A patch release on [0.81.6](0.81.6.md).

## Fixes

- **The standing-twin warning compares names the way the link-wait router does.** It used to compare names case-insensitively after trimming the ends only. Now runs of whitespace inside a name count as one space too (`src/namefold.ts`, used by both). So `work-on  API watch` and `work-on api watch` are twins. The warning now states the actual harm: a link wait that names the session as its owner matches both mains, so it goes to every standing main instead of to one.
- **A resident tower answers an integrator's `train:` departure** with the train's session id or the refusal. The integrator waits for that answer, and with tower runs off it used to get none.
- **A reply that answers a link wait says which wait it closed.** Its `link_reply` header carries `wait=L<n>` beside `for=<tower>`, so the raiser can tell which of its waits is done. Before, the box main in the live check got the answer with no wait id.
- **The remote-request dialog names the sender's trust level.** Below `dispatch`, it also says that at `dispatch` such calls run unasked, so the boss knows how to stop these dialogs for a device he trusts, such as his own unattended box. A remote turn's refusal of `link_request` now says that a trust change is asked from a local turn. On 11/21 the Mac trusted the box at `forward` only, so every gated call in a box-woken turn asked the boss, and nothing said why.

## The boss's delegate

- **A device can name a teammate device as the boss's delegate, and its main decides the cards that would have gone to the boss.** The boss asked for it on 2026-11-21: 「每次無人塔台幹嘛我都要核准，也太煩了吧，你不能幫我核准嗎」 and 「代理人什麼都能核准，除非他覺得應該問我」. Set `link.delegate {device, owner?}` in config.json on an attended device, or `delegate` in `/etc/straw-link/policy.json` on an unattended box; `/boss link status` shows it. A tower run's card for the boss, and the wait router's own card for a teammate's wait, then go to that device's standing main (or the main `owner` names) as a link wait of kind `approval`. That main may approve anything with `call_tower` `linkWait {state: "done"}`, and leaves to the boss what it judges he should decide with `why: blocked` and `state: "escalated"`. The tower hears an approval as a server notice in the delegate's words, never as the boss's press. An escalation, a decline, no main there, 10 minutes with no main taking it, or 7 days with no answer put the card on the boss's list as before, saying why. The delegate must be at `dispatch` on the raising device and run this build (`tower.approval`); otherwise the card goes to the boss as today. A secret card, one marked `bossOnly`, one a train or an integrator raised, and a restatement always go to the boss. Design: [box-mac-waits §15](../specs/2026-11-21-box-mac-waits.md).
