# pi-straw-boss 0.116.2

Released 2026-11-28. A patch on [0.116.1](0.116.1.md).

## Changed

- **The car and question probes say which session they answer for.** `straw-boss:car-rows:v1` and `straw-boss:ask-rows:v1` now answer `{ version: 1, session, rows }`. The new `session` field is this session's id as the rows name it, so pi-todo-ledger can put a car or a question under its own todo and never under a subagent's todo that has the same id. The field is additive and the version stays 1; a reader of 0.116.1 sees no difference. See the [car rows](../specs/2026-11-28-car-rows.md) and [boss asks](../specs/2026-11-28-boss-asks.md) specs.
- 車廂與問題的探針會說明它們代表哪個 session。`straw-boss:car-rows:v1` 和 `straw-boss:ask-rows:v1` 現在回覆 `{ version: 1, session, rows }`。新的 `session` 是這些列用來稱呼這個 session 的 id，pi-todo-ledger 因此能把車廂或問題放在自己的 todo 底下，不會掛到子代理同號的 todo。這是新增欄位，版本號仍是 1；讀 0.116.1 格式的程式看不出差別。
- An Ask's todo is bound with that todo's `uid` as well as its id, whenever the binding knows it: the asker's own list for a `call_tower` question, and the bridge's todo summary for a mirrored question (`todo.doingUid`, `todo.runs[].uid`). pi-todo-ledger reuses ids after `clear`, so a reader checks the uid and no longer marks a new todo with the old id as blocked.
- 問題所卡住的 todo，現在除了 id 之外，也會在知道的時候一併記下 todo 的 `uid`：`call_tower` 的問題取自提問者自己的清單，鏡像的問題取自 bridge 的 todo 摘要（`todo.doingUid`、`todo.runs[].uid`）。pi-todo-ledger 在 `clear` 之後會重用 id，讀取端核對 uid，就不會把同號的新 todo 標成被卡住。

## Performance

- The car probe answers at once, without reading the session's branch, while the session has no car and no unreceived slip. With cars, it parses the todo list again only when the branch's newest snapshot changed.
- 這個 session 沒有車廂、也沒有尚未被收下的車廂單時，車廂探針會立刻回覆，不讀 session 的分支。有車廂時，只有分支上最新的快照變了，才會重新解析 todo 清單。

## Known limits

- While the session has cars, each probe still asks pi for the branch (`getBranch()`), which pi builds from the leaf to the root every time. pi-todo-ledger asks every 5 seconds and at each draw, so the cost grows with the length of the session while cars are on their way; only the parse is saved.
- 這個 session 有車廂時，每次探針仍會向 pi 取一次分支（`getBranch()`），而 pi 每次都從葉節點一路建到根。pi-todo-ledger 每 5 秒和每次重畫都會問一次，所以車廂在路上時，成本會隨 session 長度增加；省下的只有解析。
