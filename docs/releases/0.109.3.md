# pi-straw-boss 0.109.3

Released 2026-11-27. A patch release on [0.109.2](0.109.2.md).

## Fixed

- **sb closes panes, never a tab with other panes in it.** Herdr closes a tab when its last pane closes, and a workspace when its last tab closes, so sb now closes only the pane it owns and leaves the rest to Herdr. `boss_wrap` already closed only the main's own pane, and a test now holds it to that: a worker, the boss's shell, or another main beside it stays, and so does the tab. Several other paths closed the whole tab and now close one pane:
  - a tower that loses the race for its workspace;
  - **Quit tower** on the server's tower, whose tab may also hold the boss's splits (its ally runs' panes still close with their runs);
  - `boss_close_main {pane}` on a dead pane that was its tab's only pane;
  - the old tab of a revived main;
  - leftover tower tabs;
  - an open, revive, or handover that fails and undoes the tab it made. A pane the boss split into that tab while pi waited on its trust question now stays.

  A squad's or base's **Quit**, a stash, and a workspace sb has just made and fails to mark still close the whole tab or workspace: closing it is what the boss asked for, or sb made it a moment earlier. See [Wrapping up an idle main](../how-it-works.md#wrapping-up-an-idle-main).
- sb 現在只關它自己的 pane，不再關掉還有其他 pane 的分頁。分頁的最後一個 pane 關掉時，Herdr 會自己關分頁；工作區的最後一個分頁關掉時，Herdr 也會關工作區。`boss_wrap` 原本就只關主智慧體自己的 pane，現在有測試確保旁邊的 worker、老闆的 shell 或另一個主智慧體，以及分頁本身都留著。以下幾個原本會關掉整個分頁的地方，現在只關一個 pane：
  - 在工作區塔台競爭中落敗的塔台；
  - server 塔台的「關掉塔台」，老闆在它分頁裡切出的 pane 會留著，ally run 的 pane 仍會隨它們的 run 關掉；
  - `boss_close_main {pane}` 關掉的死窗格，即使它是分頁裡唯一的 pane；
  - 救回主智慧體時的舊分頁；
  - 遺留的塔台分頁；
  - 開啟、救回或交接失敗時，收回自己剛建立的分頁。pi 等信任確認時老闆切進那個分頁的 pane，現在會留著。

  小隊或基地的「關掉」、收起，以及 sb 剛建立卻沒能標記的工作區，仍會關掉整個分頁或工作區：這是老闆要求關掉的，或是 sb 前一刻剛建立的。
