# pi-straw-boss 0.81.0

Unreleased. A feature release on [0.80.17](0.80.17.md), from the boss's auto-mode requests and the box ↔ Mac friction of 11/19–11/21.

Upgrade the attended computer first, then the unattended box. The new wire fields go only to a peer whose caps list them, so a 0.81.0 Mac and a 0.80.x box (or the reverse) keep talking in the old form until both are on 0.81.0.

## Added

- **Waits between devices.** A main on one computer that waits on another computer's action marks it with `call_tower` `waitsOn` (`why: blocked`). Its tower forwards it with `tower_send waitsOn`, and `tower_done` is refused while such a wait is neither forwarded nor answered. On the receiving computer the server routes it in code, with no model in the path: to the main the wait names, else to every main of the workspace, else, after 30 minutes nobody claimed it, to a card on the boss's list (at most three cards per device; the rest fold into the third). The wake carries no word of the other computer's; the main reads the wait with `board_read` and answers with `call_tower` `linkWait`. Each step goes back to the sender. See [Waits between devices](../how-it-works.md#waits-between-devices) and the [spec](../specs/2026-11-21-box-mac-waits.md).
- **`ally_escalate`.** An ally run at any trust level can hand an ally notice that names a local main, or says no local main owns the work, to the same router instead of closing it.
- **A tower run's device send binds the main that asked.** A bare `tower_send` to a device from a run started by one main's ask expects a reply for that main. A reply that finds the main busy is held until its ask expires (24 h) instead of falling to an ally run after 5 minutes. An unattended box answers an ask its ally run left unanswered with a receipt, and says why a message waits in its inbox.
- **Watching a box.** `watch_read` and the watchdog take `link:` keys for a teammate device's units and mains, with `idle`, `waiting` and `offline` verdicts, and `cli.mjs watch` streams them for `MonitorCreate`. A coordinator that starts a watch gets a one-time hint that `boss_duty standing` fits the job; sb never changes a main's kind itself.

## Changed

- **The head tower switches auto mode on at once.** The boss's own words to the head (「我要睡了」 and the rest of the on list) turn auto mode on without the pane's confirm, as the off words already did. The word lists, the refusal of questions, negations, two directions and reused words, and the rule that only the boss's own typing counts are unchanged. `/boss auto on` and the GUI still confirm. See the [auto-return spec](../specs/2026-11-21-auto-return.md).
- **The head waits only on its own cards.** Other towers' open cards no longer mark the head's pane blocked; its status line counts them instead.
- **Parked cards go back to whoever raised them when auto mode ends.** A card parked while the boss was away is resolved as auto mode turns off and returned to its raiser (a `wait_returned` message to a session, an event to a tower or the head), which asks again if it still needs to. A raiser that is gone closes the card as `gone`, on the end report.

## Fixes

- **The role section no longer changes mid-session.** The `straw-boss` system prompt section is rendered once per session and changes only on `boss_duty`. Tab renames, a plan's graph, role changes, a tower's digest and a run's live brief reach the agent as messages, and compaction or `/tree` resends the current guidance. Before, each change rewrote the section, and claude-bridge, which hashes the whole system prompt, re-sent the conversation uncached (53 full prompt-cache rewrites, about 8.9M cache-write tokens in 48 h on one Mac). `{{tab}}` keeps the label of the session's first run; `boss_status` has the live one. See [How it works](../how-it-works.md#how-it-works) ("The role section stays put").
- **Operate no longer reads a busy session as unreadable.** A probe with no answer is sent once more (1 s, then 3 s), and a session that still does not answer is refused as `noanswer` ("did not answer in time, try again"), apart from `unread` (pi answered that it cannot read its editor). Nothing is sent without a positive answer. See the [operate-probe spec](../specs/2026-11-21-operate-probe.md).
- **A session whose pane moved stays reachable.** The hub binds a bridge to the pane intercom places its session on now, not the pane it started in, for probes, dialogs and monitors.

## Known limits

- `idle` on a `link:` key counts from the first reading this server takes.
- A crash between auto mode's end and a returned card's delivery can lose that delivery; a stop or restart waits for it (about 5 s).
- The live check of waits between devices needs both computers on 0.81.0.
