# pi-straw-boss 0.107.0

Released 2026-11-27. A minor release on [0.106.0](0.106.0.md).

## Added

- **A checked pane close: `cli.mjs pane close <pane> [--checkout <path>] [--force]`.** It closes a Herdr pane, checks that the pane is gone (closing again at most twice, and only after reading the pane again and finding it still the same target and still closable), then stops the processes the pane left, each one only after its pid and start time are checked again. Without `--force` it closes only a dead agent pane of the caller's workspace; `--force` is the boss's override. `--checkout` must be a linked worktree's root, checked before anything closes, and its reap is a server command of its own (`procs-reap-bounded`) that takes only processes working in that root and spares the caller and its ancestors; a server too old for it refuses, and nothing closes. The answer is one JSON line with what was closed, reaped and `left`; exit 1 when anything is left.
- **`train status --watch [--every SECONDS]`** prints a `{"progress":…}` line on every look (default 60 s), so a monitor running it never times out on a quiet train; the full status comes with the first look and with each change. It waits for its reader and ends with it.
- **Ward a worker in a plain pane: the main-only tool `sb_ward`.** The server looks at the pane every 20 s and wakes the main only when the worker finished (a `call_peer` report delivered to that main, or a quiet turn with nothing of its own still running, twice 60 s apart), is blocked (Herdr blocked, or a question tool waits), or is dead (pane gone, pi gone, or another session in it). Idle while the worker's own monitor, loop, watch or subagent runs is not a wake. A ward is bound to the main's car-book registration secret: add, stop and the ward's file in a list need it. That secret raises the bar; it is not proof against another process of the same OS user. Wards live in `wards.json`, so an older server leaves them alone. `cli.mjs ward` is retired and points to `sb_ward`.

## Changed

- **Watch wakes survive a restart.** A change the server found but had not delivered is saved with the read position that found it and sent again after a restart, with the same id; the main drops an id it already took. An ending (finished, dead, gone, expired) is final and is resent every minute until the main takes it, for at most 6 hours, or until its session has been off the net for 15 minutes. A non-ending change is checked against the first fresh read before it is sent.
- **One car-book registration per pi process.** `train_car`, its background check and `sb_ward` share it, and a late refusal of an old secret no longer erases the new one.

## Fixed

- Four timing races in the test suite that failed the Publish workflow now and then (link receipts, server upgrade, test isolation, link boards).
