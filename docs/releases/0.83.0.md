# pi-straw-boss 0.83.0

Unreleased. A feature release on [0.82.1](0.82.1.md): a lighter main. The boss's words (2026-11-23): 「B1 可以做」. Design: [lite-main](../specs/2026-11-23-lite-main.md) for B1, and [lite B2, D, E, F](../specs/2026-11-23-lite-b2-d-e-f.md) for B2 and E (the boss's decisions: b2_scope=trim, b2_names=boss_all, e_ask=tool, e_cli=retire, e_busy=followup). B1, B2 and E ship together, so each session rewrites its cached prompt prefix once.

## Changed

- **No graph steer.** A plan's graph (`metadata.graph`) no longer brings `dispatch.md` and a graph addendum into the conversation, and a change of the graph sends nothing. One session had about 8 such steers, each repeating the same text. The dispatch rules are now part of `main.md` for every kind: split work by owning app, a todo before each worker, `blockedBy` for dependent tasks, worktrees for parallel writers, work independent of the main's chain to subagents in parallel. `dispatch.md`, `graph-fan-out.md`, and `graph-orchestrator-worker.md` are gone; `planning.md` stays the reference for the plan's todos and anchors. The page still shows the graph beside the kind.
- **No plan-first block.** A `worker` dispatch is no longer refused with `sb: plan first` until the todos name a graph.
- **At most 4 workers per main.** A fifth `worker` subagent of one session, running or starting in the same message, is refused with `sb: 4 workers run for this main already …` until a result comes back. Scouts, planners, reviewers, other roles, and resumes are not counted.
- **The role section stays put through `boss_duty`.** 0.81.0 pinned the `straw-boss` system section for the session but let `boss_duty` rewrite it. A kind change now reaches the main as one steer of the new kind's whole prompt, as a role change already did, and the section keeps its bytes until the next session start.
- **Fewer tools where they cannot be used.** `train_car` is registered only in a train and in a session whose project's apps.json names an app with `integration` (about 2,000 characters of description and schema on every turn elsewhere). `link_request` is registered only where Straw Link is set up and the computer is attended (about 2,100 characters); an unattended computer refused every call anyway. Both are decided at the session start, so a change of the integration switch or of Straw Link inside a session leaves the tool list as it was. `boss_server` stays: mains call it.
- **Shorter tool descriptions (B2).** The main's tools keep their names; their descriptions and parameter texts are trimmed to what changes a call: `call_tower` 3,568 → 2,608 characters, `board_set` 1,653 → 680, `boss_wait_ask` 1,414 → 802, `board_read` 976 → 680, `boss_broadcast` 866 → 524, `boss_handover` 759 → 521, `boss_duty` 572 → 474, `boss_rename` 441 → 207, `boss_promote` 208 → 157. The rules in them stay word for word: `board_set`'s "no secrets, credentials, customer data, or paths outside the project", `call_tower`'s three points, and `boss_wait_ask` over `ask_user_question`.

## Added

- **`boss_watch`: the sb server watches for a main.** A main or a train calls `boss_watch {key, quiet?, idle?, until?}` and the server wakes it with one line per change of the unit: a state change, a stall (`quiet`), an idle spell (`idle`), a link wait, a device offline, the unit gone, or the watch expired (`until`, default 6 h, at most 48 h). At most one message per watch a minute, the newest state only (a line equal to the last one sent is dropped), 12 an hour per session; the changes after those come as one summary line when the hour turns. While the main works, the line waits for the end of its turn (a follow-up), and it never interrupts a turn. `stop: true` ends a watch; no key lists them. The watches are kept in the server's `watches.json`, so a `/reload` and a server restart keep them without repeating a change. The line comes from the workspace's tower identity on the `straw-boss/control` channel, so `boss_watch` needs tower runs on, and a member, a tower, and a teammate's turn are refused. A coordinator that starts a watch gets the standing hint once. See [Watches](../how-it-works.md#watches).

- The sb server prunes stale role records, ended train state, and missing workspace towers at startup and daily; `cli.mjs prune --dry-run` previews the counts without changing state.
- With `ledger.janitor` configured, the head tower wakes once each morning to sweep and route what the janitor could not clear.

## Removed

- **The `watchdog` role and its two tools.** `roles/watchdog.md`, `watch_read` and `watch_report` (2,696 characters in every child), the server's `watch-report` route, and its three-file tie are gone; a watchdog woke 6 to 30 times an hour per watched unit to forward the verdicts the server already computed. `boss_watch` replaces it. The pack ships 6 roles. A role named `watchdog` in a global or project folder still launches, as an ordinary child with no watch tools; the sidebar and the page show no dog for it. For one release the server still answers `watch-read` (a watchdog of an older build calls it) and answers `watch-report` with `watch-report is retired in pi-straw-boss 0.83.0`.
- **`cli.mjs watch`.** It exits 2 with `` `watch` is retired in 0.83.0 `` and names `boss_watch`; a `MonitorCreate` that still starts it ends at once. `duty-standing.md` now says to watch with `boss_watch`.
- **`boss_status`, folded into `board_read`.** `board_read` answers a section `towers` with what `boss_status` gave (this workspace's mains and kinds, its tower, the head tower and auto mode, the other towers), in tower runs too; a member, which `board_read` refused, gets that section alone. The server's texts and a tower run's brief name it `board_read (was boss_status)` for this release, and the server still answers a run's `boss_status` from an older build. `/boss status` stays.

## Sizes

A coordinator's section grows from 4,880 to 5,493 characters (integration off: 2,821 to 3,415) and stays cached for the session. In exchange it gets no graph steers (5 steers and 1,937 characters over one plan in the test world), no plan-first refusal, and no uncached resend of the conversation at `boss_duty`. A main has 11 to 13 sb tools instead of 13. Measured on a promoted main with no Straw Link and no train (`tests/tools-budget.test.ts`): 11 tools and 11,594 characters on 0.82.1 (including B1), 11 tools and 8,753 characters now (`boss_status` gone, `boss_watch` 1,140 new), about 2,800 characters (roughly 750 tokens) less on every turn. A child carries no sb tool any more (2,696 characters before).

## Upgrade notes

- A session that has not reloaded keeps `boss_status` and the long descriptions until its next `/reload` or pi start; the server answers both forms this release.
- A `MonitorCreate` that runs `cli.mjs watch` ends at once with exit 2: replace it with `boss_watch`. A watchdog subagent of an older build that is still running reads on, and its `watch_report` is refused.

- A session that started on 0.82.x and holds a graph steer gets the whole role prompt once at its first run after the upgrade, since the steer it holds no longer matches what the briefing would send.
- A team set up during a session gives that session's main `link_request` at its next `/reload` or pi start.

## pi-anchorloop 3.0.0

- A successor that `boss_handover` opens is told to take up the handoff todo and file the handoff names, not a loop book id.
- `anchorloop-second-thought` no longer counts as a message that starts a child's turn when a restored subagent's last turn is read (`cut.ts`); pi-anchorloop 3.0.0 sends none. An aaaav second-thought still counts.
