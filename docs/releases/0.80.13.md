# pi-straw-boss 0.80.13

Released 2026-11-18. A fix release on [0.80.12](0.80.12.md).

## Fixes

- **A phone can copy a whole message from the GUI.** Each message in a unit's comms log (the page, and Zen's companion log and its history) has a **Copy** button: the boss's message, an agent's (its markdown as written), and an incoming notice. It works over plain http on the LAN, where the browser has no `navigator.clipboard`: the text goes through a selected off-screen textarea and `execCommand("copy")`, called in the tap itself. The button says Copied for a moment; when nothing can copy, it selects the message, the button says Selected, and its tooltip and screen-reader text say to use the browser's own Copy. A notice's Copy shows when the notice is expanded. The button's state is announced, and the focus goes back where it was after the copy. The words are in English and Traditional Chinese.
- **Text selected in the log stays selected.** A long press selects a word and its handles move the selection; the browser sends the page no touch event for them, so the log took a selection for a finger at rest. An entry that arrived while the log followed its end jumped it to the bottom, and a tool result redrew the very message being read (the result lands on the newest message, which is the one a reader selects in), so either dropped the selection or broke a handle drag. While text is selected in the log, nothing scrolls it and no message holding the selection is redrawn; entries that arrive meanwhile count in the "N new" button, which clears when the log lands at its end; when the selection ends, the result is drawn and a log that followed its end lands there.
- **The phone drawer no longer takes a selection's drag.** A long press selects a word at once and the finger that goes on moving drags the selection's end (iOS sends it as touchmoves of the same touch). The drawer decided at touchstart, before any text was selected, so a flat move pulled the drawer out and cancelled the selection with `preventDefault`. Text selected after the touch began is now the page's, as text selected before it already was. A selection left over from before a touch does not stop a swipe that closes the open drawer.

## Known limits

- A tool result that arrives for a message the reader has selected text in is drawn when the selection ends, not at once.
- Copy covers the messages of the log. A tool card's arguments and output stay selectable text, with no Copy button of their own; the wait card's Copy of a command keeps its own behavior (it selects the command where the clipboard is refused).
- The checks drive a selection from script and the Copy button from a tap in an emulated phone; the long press and handle drag themselves were not run on a physical phone.
