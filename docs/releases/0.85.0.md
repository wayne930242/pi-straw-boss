# pi-straw-boss 0.85.0

Unreleased. A feature release on [0.84.0](0.84.0.md): headless tower runs, behind a switch that is off by default. Design: [lite B2, D, E, F](../specs/2026-11-23-lite-b2-d-e-f.md) §4 (the boss's decisions: f_conv=headless, f_close=view, f_rollout=switch, f_restart=drain) and its addendum [F entry](../specs/2026-11-23-f-entry.md) (fe_park=park_notice, fe_viewer=working, fe_address=both, fe_tower_cmd=own, fe_midturn=wait_stop), built at the boss's minimum: the main panes stay the usual way to talk, and the head's viewer serves zen or lazy mode.

## Added

- **`towerRuns.headless` in `config.json`.** With it on, every tower run (event runs, boss conversations, head runs, ally runs) is `pi --mode rpc` as the sb server's own child: no pane, no `herdr agent start`, no typing. The run claims with the PID the server spawned and a per-run nonce from its environment, which drops the server's, Herdr's, and any subagent or intercom identity. stderr goes to `tower/<ws>/runs/<run8>.stderr`, capped. See [Headless runs](../how-it-works.md#headless-runs).
  - Only the server writes a run's stdin, and only `abort`, `extension_ui_response`, and `get_state`. The boss's words reach the model as a `straw-tower` message, so a line that starts with `/` or `!` stays text.
  - A run that exits without `tower_done` is crashed at once; one that stops polling for 30 seconds is killed (its process group, or `taskkill /T /F` on Windows). A server restart drains: up to 60 seconds for each run to settle, then it ends, and a boss conversation resumes its session at the boss's next word.
- **A service needs no tab.** The head's forward, an ally wake, and a controller's open make none. A session's `ensure-tower` on an attended device asks for a viewer tab, which the server types into once, with `exec`, before the viewer's first poll and within a minute of making it (`onceGate` in `typegate.ts`), and never again. A viewer that ends closes its pane; the service goes on.
- **The viewer** prints the run's live text above its input (`│`, `▸`, `✓`/`✗`, `·`, `?`), cleaned on both ends and never read as a card. Typed alone: `/stop` aborts the run's turn, `@<workspace> <text>` sends the boss's words straight to that tower (`head-event` with `to`), and `/yes N`, `/no N`, `/pick N` answer a run's dialog. A dialog nobody answers is cancelled after 60 seconds.
- **The head parks notices.** A `tower_send` with `reply: false` and no `relay=boss` to a workspace with no service and nobody joined opens nothing: it waits there as a quiet event (the same text replaces the last), the ask reads `parked` on the head page, and the next run there takes it.

## Changed

- Nothing, with the switch off: the pane path of 0.84.0 runs as before, and the new control fields (`ensure-tower` `view`, `head-event` `to`, `run-abort`, `run-dialog`, `prompt-poll` `cursor`) are refused or ignored.

## Not in this release

- The Windows VM and box passes of headless runs; the switch stays off until they are green, and the release after them deletes the pane path.
- `/to`, `/runs`, and the head viewer's `focus`; the head brief's lines for direct conversations and parked counts; an ask's `expired` state; answering a run's dialog on the local page; the `door: viewer` rename.
- A head viewer that closes ends the head as its tab did before.

## Upgrade notes

- To try it, set `"towerRuns": { "headless": true }` (and `"pi"` when the `pi` on the server's `PATH` is not the one) and restart the sb server. A tower's existing standing pane stays a shell the server no longer types into; close it, and `/boss tower` makes a viewer.
