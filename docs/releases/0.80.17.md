# pi-straw-boss 0.80.17

Unreleased. A fix release on [0.80.16](0.80.16.md), from the merge-train friction an integrator reported on 11/20.

## Added

- **`train end` ends a stale train.** A train whose cars all left, or whose session died after its merge, never completes a `land` step, so its board stayed `stale` and the watch reported it as stalled. `cli.mjs train end --project P --train CODE --outcome landed --commit SHA` (or `--outcome none`) `--reason TEXT --evidence TEXT` writes the end to `end.json` beside the train's `board.json`, which keeps the schema 0.80.16 reads. From then on the train reads as ended: it holds nothing, the watch drops it, and the folder is deleted 7 days after the end. Only a stale train can be ended. A live, ended or unreadable one is refused, as `train clear` refuses one, and so is a train that still holds a deploy target: read what the target runs and `train clear --target` it first.
- **`train status --state`** keeps the rows in the states it names (`live`, `stale`, `ended`, `unreadable`, comma separated), in text and `--json`. An ended train shows its end.

## Fixes

- **A restart no longer cuts a running train.** The server keeps the car book and which train it opened in memory, so a restart in the middle of a train got its land step refused ("this server did not open train …"). `cli.mjs restart`, `boss_server restart` and a tower run's restart are now refused while a train runs, and the refusal names the train. `cli.mjs restart --force --reason TEXT` restarts anyway, and `cli.mjs up` refuses its upgrade or desk-switch restart the same way, with the same `--force --reason`. The boss's `/boss server restart` goes ahead, and its confirm names the train. The GUI's Restart button also goes ahead, without naming the train. A session's automatic upgrade waits until no train runs, and the server's log says so once (`upgrade-deferred`, with the trains).
- **`train check` checks the slip's head in git.** The head must be a commit git knows, and it must be the tip of the slip's branch on origin. A mistyped head, an older commit, or a branch that is not on origin is refused, and the refusal names both commits. An origin that cannot be asked is a warning.
- **`train check` runs from an app's folder.** An app that is a repository of its own (a submodule) has no apps.json at its root, so the check now walks up to the project's. Without `--app-accept`, the app's `integration.accept` is required, as it was already; the usage now says so.
- **The train prompt** takes a step's `load` from the project skill or apps.json and never from a manifest note. Before it marks a merge or land failed on a tool error, it asks git whether the head landed. A train that merges nothing ends with a failed `land`, so its board ends instead of going stale.

## Known limits

- A train whose session comes back after `train end` writes its board again, and from then on its `end.json` is ignored (the board is newer than the end): it is live again.
- The restart guard sees a train by its board. A train the server opened that has not yet written its board (before its first todo) is not seen.
- The car book still lives in the server's memory. The guard keeps a manual restart from cutting a train, but a crash still cuts one.
