# pi-straw-boss 0.75.2

Not yet released.

A project opened from the page while auto mode is on asks its trust question instead of being refused at once.

## Fixes

Desk #51, 11/11: a desk PM who opens a project from the GUI while auto mode is on got a session without the project's `.pi` resources, because pi's trust question for the new pane was answered "not trusted for this session" at once (auto mode's D3: nobody is there).

- **A project opened from the page asks its trust question.** A pane started by `POST /api/open/base` carries a person's intent, so under auto mode its question is asked as usual (the GUI, or the terminal when no GUI answers), as with auto mode off. Every other pane keeps D3's answer. The intent is the sb server's own, in its memory only: before pi starts the server lists the pane with the folder it starts pi in, and takes it off when the open's start and join end, however they end. The asking pi asks the server over the control socket (`open-intent`, with its own pane id and folder) and takes only the server's yes; nothing in the request or in the pane's environment can add a pane to the list, and nothing is written to or read from disk for it. `open/member` and `open/main` and the `POST /api/open/base` request itself are unchanged.
- **When the server cannot say.** No sb server, one that does not answer within 10 s, an older one (it does not know `open-intent`), and one that restarted while the project was opening (its list is new) all give D3's answer, as before this release: the session opens without the project's `.pi` resources, and auto mode's return list shows the refusal. Open the project again.
