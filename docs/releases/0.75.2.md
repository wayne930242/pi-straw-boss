# pi-straw-boss 0.75.2

Not yet released.

A project opened from the page while auto mode is on asks its trust question instead of being refused at once.

## Fixes

Desk #51, 11/11: a desk PM who opens a project from the GUI while auto mode is on got a session without the project's `.pi` resources, because pi's trust question for the new pane was answered "not trusted for this session" at once (auto mode's D3: nobody is there).

- **A project opened from the page asks its trust question.** A pane started by `POST /api/open/base` carries a person's intent, so under auto mode its question is asked as usual (the GUI, or the terminal when no GUI answers), as with auto mode off. Every other pane keeps D3's answer. The intent is the sb server's own record, `open-intents-<slot hash>.json` in the state folder (mode 600): before pi starts the server lists the pane with the folder it starts pi in, and takes it off when the join ends, however it ends. The asking pi finds itself there by its own pane id and folder; nothing in the request or in the pane's environment can add a pane to it. `open/member` and `open/main` and the `POST /api/open/base` request itself are unchanged. A list the server cannot write is logged as `open-intent-failed` and the open goes on with D3's answer.
