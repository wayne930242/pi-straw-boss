# pi-straw-boss 0.117.0

Released 2026-11-28. A minor release on [0.116.3](0.116.3.md).

## Added

- **A todo's detail shows what its runs spent.** With pi-todo-ledger 0.10.0, a run bound to a todo records its tokens, cost, wall time, runs and models on that todo when it ends. The total covers every run of the todo and every fallback attempt. The session page shows the totals in the todo's detail line (`Spent: 4,800 tokens · $0.75 · 2m · 2 runs · anthropic/claude-opus-5-5`). Session paths and run ids stay out of the page. The figures are an estimate from the child's transcript, not a bill. See [The subagent host](../how-it-works.md#the-subagent-host) and the [spec](../specs/2026-11-28-todo-preflight.md#b-run-spend-on-the-todo).
- todo 的細節會顯示它的 run 花了多少。搭配 pi-todo-ledger 0.10.0，綁定到 todo 的 run 結束時，會把 tokens、費用、實際耗時、執行次數與模型記在那個 todo 上。總數涵蓋這個 todo 的每個 run 與每次備援嘗試。session 頁面在 todo 的細節那一行顯示總數（`花費：4,800 tokens · $0.75 · 2m · 2 次執行 · anthropic/claude-opus-5-5`）。頁面上不會出現 session 路徑與 run id。這些數字是從子代理逐字稿估算出來的，不是帳單。
- **Every run's end is told by its run id.** The subagent host now runs on Maestro `sb-host-a5a9c43`. Maestro names on each `subagent_result` and `subagent_ping` the run id its launch acknowledged, the run's elapsed time (a ping's too), and every spawned attempt. As each end goes out, the host sends `subagent:run-end` `{ v: 1, id, kind, name?, item?, sessionFile?, elapsed?, attempts? }` on `pi.events`. An end the model never reads, such as a steer cleared before its turn, is still counted. The host no longer guesses a run from its name or session file. An end without a run id sends no event.
- 每個 run 的結束都以 run id 標明。subagent host 改用 Maestro `sb-host-a5a9c43`。Maestro 在每個 `subagent_result` 與 `subagent_ping` 上標明派工確認的 run id、run 的實際耗時（ping 也有），以及每次啟動的嘗試。每個結束送出時，host 會在 `pi.events` 上送出 `subagent:run-end` `{ v: 1, id, kind, name?, item?, sessionFile?, elapsed?, attempts? }`。模型沒讀到的結束（例如在輪到它之前就被清掉的 steer）也照樣計入。host 不再靠名稱或 session 檔猜是哪個 run。沒有 run id 的結束不送事件。

## Known limits

- When Maestro's second read of a resumed run's summary fails as it delivers the end (the session file moved or became unreadable), Maestro sends neither the result nor the host's event, so that end is not counted, not even its time.
- Maestro 交付續跑結果時，若第二次讀摘要失敗（session 檔被移走或讀不到），它既不送結果，也不送 host 的事件，所以這次結束完全不會計入，連時間也不算。
- Spend writes skip the ledger's change guards, so sb's train guard never sees them. They change only `metadata.herdr`.
- 記帳寫入不經過 ledger 的變更關卡，所以 sb 的 train 關卡看不到它們。這些寫入只改 `metadata.herdr`。
