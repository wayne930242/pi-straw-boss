# pi-straw-boss 0.91.0

Released 2026-11-26. A minor release on [0.90.0](0.90.0.md). Design record: [2026-11-25-idle-wrap-up.md](../specs/2026-11-25-idle-wrap-up.md), part 2.

Rules a main needs at one moment are now delivered at that moment, by code or by the text that arrives then, instead of in its standing prompt (boss, 2026-11-25). `main.md` and `tower-run.md` are back to 0.89.0's text, except that a returned wait is asked again with `call_tower` `boss`.

## Added

- **`call_tower` `boss`: the boss's question drawn by code.** A `blocked` call may carry `boss: {question, options?}` for a decision only the boss makes. With auto mode off, in a tab main's own turn on an attended device, sb asks it in that main's pane and relays it to the GUI and paired devices as a questionnaire (pick an option, or type an answer; a question with no options takes a typed one). The first answer, from either side, is the tool's result, quoted as the boss's; nothing goes to the tower. Escape says the boss did not answer. Under auto mode, or when it starts while the question is open, the question goes to the tower as `blocked` with the message, is parked, and comes back as `wait_returned` when auto mode ends. A remote turn, an unattended device, a session with no terminal, a member, a train, and a tower send it to the tower as before.

## Changed

- **The wrap-up rule is only where it is needed.** `main.md`'s done rule is 0.89.0's again; the steps (answer owed asks, remove worktrees, settle todos, stop monitors, a daily memory entry, then `boss_wrap`) are in the idle nudge and `boss_wrap`'s own text.
- **0.90.0's prompt rule for boss questions is gone.** The main no longer reads a standing rule to ask with `ask_user_question`, and the tower run's auto-off rule is removed: with auto mode off a boss question never reaches the tower.
- A returned wait (`wait_returned`) and the auto mode end notice say to ask again with `call_tower` `boss`.
