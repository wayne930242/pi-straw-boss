# pi-straw-boss 0.81.3

Unreleased. A patch release on [0.81.2](0.81.2.md).

## Fixes

- **A main an ally run opened can wait on the device that opened it.** Its `call_tower` with `why: blocked` and `waitsOn` used to reach that device's ally runs, which forward no wait, so it arrived as a plain message, the other end could only escalate it, and the answer came back as a new incident instead of reaching the main. The sb server now forwards such a wait itself, as a tower run forwards a local main's: with the wait field and the main's ask, recorded in the workspace's ledger, so each step and the answer reach the main. Nothing of it enters a run here. A wait on any other device is refused with a message that says which device opened the main.
- **A teammate's wait goes to the main that owns it, not to everyone, and not to the boss by default.** A wait that names no main here went to every main of the workspace, and a told wait nobody claimed in 30 minutes became a card. Now it goes to the main it names, else to the workspace's standing main (the counterpart of a teammate's unattended tower), which answers it with `call_tower` `linkWait` or asks the boss itself when the decision is not its own. A card comes only when there is no main to tell or the told main is gone.
- **Link cards say what is waited on.** A card for a teammate's wait used to read only "find who here owns it". It now says what the device waits on, quotes an excerpt of its message as the teammate's words, names who was told, and says what done and decline each send back, in both languages. The fold line on a device's third card names the device too.
- **A notice no longer becomes a wait.** A teammate's message that expects no answer and does not say it waits on this computer, such as a report that something is done, opened a wait when an ally run escalated it, and its cards then asked the boss to handle it. The server now records it as a notice, decided from the message itself and not from the ally run's choice of kind: the standing main hears it as information, no card is raised, nothing goes back, and it lapses after a day.
- **Mains have `board_read`.** A main told of a teammate's wait (`kind=link_wait`) is sent to `board_read` section `waits`, which only towers had. Every main now has it, with the waits of its own workspace in both directions; a remote turn sees what it saw before.

## Known limits

- The server marks an opened main's wait seen and receipts it before the send to its opener settles, so a crash in that window loses the wait without telling the main; the main can raise it again.
