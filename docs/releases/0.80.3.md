# pi-straw-boss 0.80.3

Unreleased. A fix release on [0.80.2](0.80.2.md).

## Agent kinds

Three leftovers of the agent-kinds phase 2 net work, listed as not done in its report.

- **`board_read` rows name each main's kind.** Shared contract 8 of the [spec](../specs/2026-11-09-agent-kinds.md) lists it as optional. Each `local` row now carries `kind`: `coordinator`, `integrator`, or `standing`, read from the main's `sb_duty` as `tower_list` and `boss_status` read it. It is `null` for a train, for an ended entry, and for a main that publishes none (an older sb, or a value the net does not know), and the key is on every row. In a remote turn the rows the senders may see carry the same word `tower_list` already gives them; an ally's `remote` rows carry none. The tool description says so. See [The work board](../how-it-works.md#the-work-board).
- **A standing main's handoff promises no close.** The text a main receives from `boss_open_main` ended with "the tower closes this tab after your done report", which a standing main, with no end and no done report, cannot act on. A main opened with `duty: "standing"` is now told to set up the watch its prompt describes, to tell the sender once (the tower, for a teammate's request, with the same rule for a report that can leave the computer) what it minds and its state, and that the tower does not close its tab: it stays until the boss closes it. A coordinator's handoff, and one with no duty, read as before, byte for byte. `boss_close_main` refuses a standing main in both tool paths (the session tool and the server's run tools): only the boss closes it. `boss_open_main` with `duty: "standing"` answers with its own line (no done report, do not close), and the tower prompts name coordinators for the close after a done report. `closeMain` itself does not refuse, so a revoke or a signed stop still ends a peer's main.
- **A child another session resumed shows once across parents.** Resumed-child dedupe worked inside one parent only. When another session resumed a child, the resume lives in that session's artifacts under a new id, and the original parent still held the first launch, recorded done beside a pane that runs on: its card showed the child as `done` next to the resumer's running row. The net and the tower's dashboard now read every parent's launches of one reading together, and of the launches of one session file the one with the newest activity wins, a resume on a tie, as it does inside one parent. The loser goes before its parent's row limit, so it never takes a slot. Two panes on one session file hold the same launches, which do not compete. A parent's own rows, with no session file shared, are as before; `subagents` for one parent (the sidebar marks, `boss_close_main`'s busy check) reads as before and still counts its own launch.

## Known limits

- The sidebar's subagent marks (`order.ts`), `board_read`'s and the tower brief's `commanding` (`boardread.ts:27`, `server/towerbrief.ts:140`), and the busy check of `boss_close_main` still read one parent at a time. A child resumed by another session is counted under the original parent there only when its first launch never recorded done (killed or cancelled); a first launch that recorded done reads as ended.
