# pi-straw-boss 0.88.0

Released 2026-11-24. A minor release on [0.87.2](0.87.2.md).

## Added

- **A worker whose pi crashes comes back.** When a subagent's own pi dies (a crash or a kill, leaving its pane and an exit code) while the main that launched it lives, Straw Boss runs the same session again in a new pane beside the main, from the launch or resume script pi-herdr-agents wrote: same folder (a managed worktree too), model, thinking, and tools, with a first message saying it was revived and should finish its task and report. Its report reaches the main as one result, and the main is told once that the worker was revived. The death a main reads says so first, so its model does not resume, respawn, or cancel the run.
- **Only a fresh, unhandled crash.** A death is confirmed by two looks a minute apart and handled once, recorded in the main's session so a `/reload` does not repeat it. A cancel, a normal end, the worker's own error, a help request, Ctrl-C, or a pane that was closed is never revived; neither is a death older than ten minutes, one a later result or a newer launch or resume script supersedes, one anything still holds, a fork run whose task was sent inline, or a run whose revive failed in the last 24 hours. A revive that cannot start, or a worker that dies again, is reported to the main once, with no retry. See [A subagent that dies is revived](../how-it-works.md#a-subagent-that-dies-is-revived).
