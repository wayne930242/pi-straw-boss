# pi-straw-boss 0.84.0

Unreleased. A feature release on [0.83.0](0.83.0.md): review threads. Design: [lite B2, D, E, F](../specs/2026-11-23-lite-b2-d-e-f.md) §2 (the boss's decisions: d_where=sb, d_attach=main_pairs, d_rounds=per_thread).

## Added

- **Review threads: a worker and its reviewer talk directly.** A main calls `boss_pair {worker, reviewer, rounds?}` before it dispatches the two, writes both briefs, and dispatches both with the line `Thread: T<n>` in their tasks. The two children post to each other on that thread through the sb server with `thread_post {thread, to, tag, text, refs?}` and `thread_wait {thread, since?}`, and the main is woken only by their two results when the thread closes. A reviewed change with r repair rounds used to cost the main 2r+3 turns and every finding twice in its context; now it costs one or two turns. See [Review threads](../how-it-works.md#review-threads).
  - The server numbers the posts `#n` and writes who sent each. Only the worker posts `review`; only the reviewer posts `fix` (one repair round each) and `done` (its approval, which closes the thread); either posts `blocked`, which closes it too. `rounds` is 1 to 3, default 3: a `fix` past it is refused, and the server closes the thread `blocked` with "N repair rounds used". The main may be named only with `done` or `blocked`, so a child cannot wake it early; a member's wait returns only the posts that name it.
  - The server also closes a thread `blocked` after 2 hours without a post, 24 hours after the pair, or when a member's run ended without a close.
  - The server sends the main nothing: the children's results, delivered by pi-herdr-agents as for any subagent, are the wake. A revived main keeps its threads (same session id) and picks up results through orphan pickup; a handover adds no wake path.
  - `board_read` lists a main's threads in section `threads`, and `board_read {thread}` shows one thread's posts, newest last within 16 KB, framed with `| ` so a child's text cannot pass for sb's; `<owner8>/T<n>` reads another main's thread on this computer.
  - The threads live in `threads/<owner8>/T<n>.jsonl` (the posts, mode 600) and `T<n>.json` in the server's folder, so a server restart keeps them; a closed thread's files go 7 days after its close.
- **Who may.** Only a tab's main or a train pairs, never in a teammate's turn; members and towers are refused, and a tower run has no `boss_pair`. Only the pairing main's two children speak on a thread: each child is tied to the main that dispatched it by pi-herdr-agents' launch script, session file, and activity file (`src/server/childtie.ts`, the tie the 0.80.0 watchdog used), and its script's name must be the thread's worker or reviewer. Another child of the same main, a child of another main, and a child whose run is done are refused. The control socket carries no peer credentials, so a process of the same user can still post a false message to one thread.

## Changed

- **The tool sets stay put.** `boss_pair` is registered with the net tools at the join, so a main has it from its session start. `thread_post` and `thread_wait` are registered in every child, inactive; at the child's first run, before its first model call, sb asks the server whether its main paired it, and only a member gets the two in its active set. Any other child has them taken out, even with the reviewer role's `tools:` line, which now names them. The answer holds for the session.
- `roles/worker.md` and `roles/reviewer.md` each gain a `## Review thread` section; `prompts/main.md` says how to dispatch a reviewed change.
- The long poll the retired `watch_read` ran is `src/holdpoll.ts`, which `thread_wait` runs: progress updates keep pi-herdr-agents' hang advisory quiet, an abort or an arriving message ends it, and a server that does not answer is asked again.

## Sizes

On a promoted main with no Straw Link and no train (`tests/tools-budget.test.ts`): 12 tools and 9,601 characters, from 11 and 8,753: `boss_pair` is 698, and `board_read` grows from 680 to 830 for `thread` and section `threads`. A child carries the two thread tools inactive; only a paired one sends them to the model.

## Upgrade notes

- A session that has not reloaded has no `boss_pair` until its next `/reload` or pi start, and a child launched by an older build has no thread tools.
- A reviewer role in a global or project folder that should take part in threads needs `thread_post` and `thread_wait` in its `tools:` line; `/boss roles-check` knows both as child-only names.
