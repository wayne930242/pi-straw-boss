# pi-straw-boss 0.115.0

Released 2026-11-28. A minor release on [0.114.2](0.114.2.md).

## Added

- **The stale reminder can be snoozed, and its interval set.** A main the sb server finds stale can hold the reminder with `board_set { snooze: { why, for?, watch?, todo? } }`: for a span (`30m`, 1 minute to 24 hours), or until one of its own `boss_watch` watches sends its next change (24 hours at the latest), for the whole main or for one open todo. A new snooze of the same scope replaces the old one. When a snooze ends and the main has not moved since, the reminder comes at the next look, once per snooze. `capacity.staleMinutes` and `capacity.staleUnattendedMinutes` in `<state dir>/config.json` set the two spans (120 and 30 minutes by default). The reminder names the unanswered todos of the whole ledger, not only the board's 200 rows, and counts the main's own last move in its session file: taking a reminder and answering it in text is no move. `board_set` keeps a snooze only when the sb server answers and runs the reminder. See [Device capacity](../how-it-works.md#device-capacity) and the [spec](../specs/2026-11-28-stale-snooze.md).
- 停滯提醒可以延後，間隔也能設定。sb server 判定主代理停滯時，主代理可以用 `board_set { snooze: { why, for?, watch?, todo? } }` 把提醒延後：延一段時間（`30m`，1 分鐘到 24 小時），或延到它自己的某個 `boss_watch` 送出下一次變化（最晚 24 小時），範圍可以是整個主代理，也可以是單一未完成的 todo。同一範圍的新延後會取代舊的。延後結束時主代理若一直沒動，下一次檢查就會提醒，每次延後只提醒一次。`<state dir>/config.json` 的 `capacity.staleMinutes` 與 `capacity.staleUnattendedMinutes` 設定兩個時長（預設 120 與 30 分鐘）。提醒列出整份帳本裡尚未回應的 todo，不只看板的 200 列；計算的是主代理自己在 session 檔裡最後一次動作，所以收到提醒後只用文字回覆不算動作。只有 sb server 有回應且有執行提醒時，`board_set` 才會保留延後。

## Performance

- **The capacity watch's minute stays cheap.** A session file is read again (its append, or at most its last 256 KiB) and a capacity file parsed again only when its stat moved (device, inode, size, and mtime and ctime in nanoseconds) or ten minutes passed; the session side projects its ledger again only for a new todo snapshot. `node scripts/bench-captick.ts 20 20` (20 mains, each with a 50,000-record ledger and a 128 MiB session file) on this Mac: a tick with nothing changed takes 1.85 ms median and 2.22 ms max (70 ms before), a cold tick 77 ms, and projecting one ledger 17 ms.
- 產能監看每分鐘的成本維持很低。session 檔只在 stat 變了（裝置、inode、大小，以及奈秒精度的 mtime 與 ctime）或過了十分鐘時才重讀（只讀新增的部分，最多讀最後 256 KiB），產能檔也一樣才重新解析；session 端只在 todo 快照換新時重新投影帳本。在這台 Mac 上跑 `node scripts/bench-captick.ts 20 20`（20 個主代理，各有 50,000 筆帳本與 128 MiB 的 session 檔）：沒有變化的一輪中位數 1.85 ms、最大 2.22 ms（原本 70 ms），冷啟動一輪 77 ms，投影一份帳本 17 ms。
